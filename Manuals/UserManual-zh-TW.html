NPSeeker 使用說明

版本 1.5.42

關於 NPSeeker

NPSeeker (Nucleic Acid Probe Seeker) 是從基因體序列設計核酸探針的程式, 主要用來替 BioFET (生物場效電晶體) 這類生物晶片挑選探針。核酸探針是一小段 DNA 序列, 能與目標生物的 DNA 結合, 用來偵測或辨識生物。

使用者給 NPSeeker 兩組基因體: 目標 (要偵測到的組別) 與對照 (不該偵測到的組別)。NPSeeker 先找出每一個目標都有的 DNA 片段, 再評估它們與對照有多像、與目標結合得多穩、會不會自己摺起來, 最後依分數排名列出候選探針。探針的長度可以設定, 5 到 256 個鹼基。

本軟體對應的研究論文與聯絡資訊:

論文NPSeeker: A BioFET-oriented Nucleic Acid Probe Design Algorithm for Efficient Species Identification and Classification
作者Hao-Yu Peng, Hui Zhi Gan, et al.
網站https://10lab.ceb.nycu.edu.tw/NPSeeker/
GitHubhttps://github.com/NYCU-10lab/NPSeeker/
聯絡WadeLo@nycu.edu.tw

使用本軟體進行研究時, 敬請引用上述論文。

關於本書

第一次使用, 請從第 0 章開始。只想用網頁介面的話, 讀完 0.1 到 0.3 節之後, 可以直接跳到 0.4 節。要準備自己的資料時, 看第 2 章; 要調整參數時, 看第 5 章。

程式本身也有說明: -h 列出常用的選項, -help 列出全部的選項, 內容與本書一致; 本書多了操作步驟、例子與建議。本書有純文字版 (UserManual-zh-TW.txt) 與網頁版 (UserManual-zh-TW.html), 內容相同; 網頁介面的 Help 頁也可以閱讀本書。

0. 快速開始

本書的指令以 macOS 與 Linux 的寫法為主。Windows 的寫法不同時, 會另外列出。

沒有用命令列跑過程式的話, 請照著這一章一步一步做。

0.1 下載適合的版本

從 NPSeeker 網站或 GitHub 下載自己作業系統的壓縮檔, 共有三種: Windows, macOS, Linux。每個壓縮檔裡都有兩種處理器架構的執行檔:

x86_64一般的 Intel 與 AMD 處理器
arm64Apple M 系列晶片的 Mac, 以及使用 ARM 處理器的電腦

不知道自己的電腦是哪一種時:

  • Windows: 打開「設定 -> 系統 -> 關於」, 「系統類型」寫 x64 的是 x86_64, 寫 ARM64 的是 arm64。
  • macOS: 打開「蘋果選單 -> 關於這台 Mac」, 「晶片」寫 Apple M1、M2 等的是 arm64,「處理器」寫 Intel 的是 x86_64。
  • Linux: 打開終端機, 輸入 uname -m 再按 Enter; 印出 x86_64 的是 x86_64, 印出 aarch64 的是 arm64。

0.2 解壓縮與資料夾內容

把壓縮檔解開到任何一個資料夾:

  • Windows: 在壓縮檔上按滑鼠右鍵, 選「解壓縮全部」。
  • macOS: 在壓縮檔上雙按滑鼠左鍵。
  • Linux: 在終端機執行 tar xzf 加壓縮檔的檔名。

解開後是一個 NPSeeker 資料夾, 裡面有:

bin/x86_64 的執行檔 npseeker (Windows 是 npseeker.exe)
bin.arm64/arm64 的執行檔
doc/使用說明
dat/sample/第一次計算用的範例資料

論文用的細菌基因體 (革蘭氏陰性菌 GN/ 與陽性菌 GP/) 要另外下載 (NPSeeker-1.5.42-datasets.zip 或 .tar.gz)。可以把它解開, 再把裡面的 datasets 資料夾 (在 NPSeeker/dat/ 底下) 搬進程式的 dat/ 資料夾裡, 就能直接照第 8 章的指令範例來測試。

NPSeeker 不必安裝, 計算時也不需要網路。本書的指令以 bin/ 裡的 x86_64 執行檔為例; arm64 的電腦請把指令裡的 bin 換成 bin.arm64。

0.3 確認程式能執行

先打開命令列視窗, 並切換到 NPSeeker 資料夾:

  • Windows: 在檔案總管打開 NPSeeker 資料夾, 在網址列輸入 cmd 再按 Enter, 就會開啟一個位置在這個資料夾的「命令提示字元」。PowerShell 也可以, 指令相同。
  • macOS: 打開「終端機」(應用程式 -> 工具程式), 輸入 cd 加一個空格, 把 NPSeeker 資料夾拖進視窗, 再按 Enter。
  • Linux: 打開終端機, 用 cd 切換到 NPSeeker 資料夾。

然後輸入下面的指令, 再按 Enter:

Windows:          .\bin\npseeker.exe -h
macOS, Linux:     ./bin/npseeker -h

畫面印出 NPSeeker 的標誌、用法與常用選項, 就表示程式可以用了。

從網路下載、沒有數位簽章的程式, 第一次執行時, 作業系統會跳出安全警告。

請先確認程式是從 NPSeeker 網站或 GitHub (「關於 NPSeeker」列出的網址) 下載的, 再照下面的方法放行。來源不明的程式不要放行。

  • Windows: 會出現藍色的「Windows 已保護您的電腦」視窗, 說 Microsoft Defender SmartScreen 已防止無法辨識的應用程式啟動, 視窗裡只有「不要執行」一個按鈕。這時先按說明文字下方的「其他資訊」, 視窗會多列出應用程式的名稱與「發行者: 不明的發行者」, 並多出「仍要執行」按鈕; 按「仍要執行」就會啟動。同一個執行檔只會問一次。
  • macOS: 系統不讓沒有經過 Apple 認證的程式執行。在終端機執行一次 xattr -dr com.apple.quarantine 加 NPSeeker 資料夾的路徑 (可以把資料夾拖進終端機視窗), 之後就不會再擋。也可以先執行一次, 被擋之後打開「系統設定 -> 隱私權與安全性」, 在下方找到關於 npseeker 的訊息, 按「強制打開」。
  • Linux: 沒有這一步。若出現 permission denied, 執行 chmod +x bin/npseeker (arm64 是 bin.arm64/npseeker) 加上執行權限, 再試一次。

0.4 用網頁介面計算

不想用命令列的話, 可以改用網頁介面, 在瀏覽器裡操作。Windows 在 bin 資料夾的 npseeker.exe 上雙按滑鼠左鍵; macOS 與 Linux 在終端機輸入:

./bin/npseeker --gui

瀏覽器會打開 NPSeeker 的介面。第一次可以用附的範例資料試試看, 在 Design 頁:

  • Target: 選 dat/sample/S.aureus/ 資料夾, 裡面是金黃色葡萄球菌的基因體。
  • Control: 選 dat/sample/yeast/ 資料夾, 裡面是兩種酵母菌的基因體。
  • Probe length: 保留預設的 25, 其他設定也先不改。
  • 按 "Check" 檢查資料與設定, 再按 "Go" 開始計算。
  • 算完後, 到 Results 頁看探針與分數, 並下載要留下的結果。

網頁介面在自己的電腦上執行, 不會連到外部網站。各頁的功能與關閉的方法見第 6 章。

0.5 用命令列計算

同一組範例資料, 也可以直接從命令列算:

Windows:          .\bin\npseeker.exe dat\sample\S.aureus\ dat\sample\yeast\
macOS, Linux:     ./bin/npseeker     dat/sample/S.aureus/ dat/sample/yeast/

幾秒內就會算完, 畫面上是依分數排名的探針 (只列出一部分):

Best probes of cluster 0:
Rank Probe                     Exclus Purity UnFold Affini  Score     Tm
   1 CCGACTAACCCAGAGCGGACGAGCC  50.84  61.32 100.00  64.22  69.10  65.88
   2 GACCCGACTAACCCAGAGCGGACGA  50.84  61.40 100.00  63.68  68.98  64.24
...

每一列是一條候選探針。Probe 是探針的序列, Score 是總分, 由高到低排列; 其他欄的意思在第 3 章。最後的 Note 提醒: 要把完整的結果存成檔案, 請加上 -o 指定一個輸出資料夾:

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

結果檔會存在 result/ 資料夾 (3.2 節)。之後再用同一個已經有東西的資料夾時, 請換一個新的名稱, 或確定舊結果可以覆蓋後再加 -w。換成自己的資料時, 把這兩個資料夾換成自己的目標與對照即可 (第 2 章)。

0.6 查閱程式說明

./bin/npseeker -help            全部的選項
./bin/npseeker -help -mode      只看 -mode (減號可以省略: -help mode)
./bin/npseeker -help Output     只看 Output 這一組選項 (各組名稱見第 5 章)

1. NPSeeker 如何設計與評分探針

NPSeeker 給它的是目標與對照的基因體, 它給出的是候選探針與排名。目標是探針要偵測到的生物, 對照是探針不該偵測到的生物 (通常是容易混淆的近親)。計算分成四步:

  • 找共同的序列: 把基因體的序列從頭到尾, 每次取連續 k 個鹼基, 取到的每一小段叫做一個 k-mer。例如 ACGTA 的 3-mer 有 ACG, CGT, GTA。NPSeeker 找出每一個目標都有的 k-mer, 當作候選; 只有大家都有的序列, 一條探針才能偵測到每一個目標。DNA 是兩股互相配對的鏈, 一段序列與它在另一股上的配對序列 (反向互補序列) 當成同一個 k-mer。
  • 過濾候選: 先去掉不適合當探針的序列, 例如鹼基組成太單調、同一種鹼基連成太長的一串 (例如 AAAA), 以及容易自己摺起來或與另一條相同的探針黏在一起的。這樣後面比較花時間的步驟, 就不必浪費在這些候選上。
  • 檢查對照: 把留下的候選拿到每一個對照基因體裡找, 看有沒有一模一樣的序列、只差幾個鹼基的相似序列, 以及候選的較短片段出現了多少次。
  • 評分排名: 依下面四項分數算出總分, 再排序。
Exclusivity專一性: 出現在目標, 而很少出現在對照
Purity純度: 對照裡的相似序列與較短片段少, 不容易黏錯地方
Unfoldability不摺疊性: 不容易自己摺起來, 保持能與目標結合的狀態
Affinity親和性: 與目標 DNA 結合得夠穩, 由結合時釋放的能量 (自由能) 算出

四項分數與總分都是 0 到 100, 越高越好。總分是四項分數的加權平均, 預設四項一樣重。這些分數是用來挑出值得做實驗驗證的候選, 不是 BioFET 訊號強度的實測值, 也不保證實驗結果。

目標彼此差異太大、共同的 k-mer 太少時, NPSeeker 會把目標分成幾群, 每一群各自找候選。分群與輸出的方式見第 4 章; 評分的公式與演算法的細節見研究論文。

2. 準備目標與對照基因體

指令的前兩項依序是目標 (target) 與對照 (control), 選項寫在它們後面:

./bin/npseeker <target> <control> [選項]

每一個基因體請準備成一個 FASTA 檔。FASTA 是存放 DNA 序列的文字檔格式, 副檔名通常是 .fasta, .fna, .fa。目標與對照各自可以用資料夾、清單檔或單一檔案指定。

2.1 資料夾

給一個資料夾時, 程式讀取裡面所有副檔名是 .fasta, .fna, .fa 的檔案, 每個檔案當成一個基因體。副檔名全部小寫或全部大寫都可以 (例如 .FASTA); 子資料夾裡的檔案不會讀取。

./bin/npseeker targets/ controls/

資料夾裡的壓縮檔 (.gz, .zst) 不會讀取。要用壓縮檔時, 請改用清單檔。

2.2 清單檔

清單檔是一個文字檔, 每一列寫一個 FASTA 檔的路徑。在檔名前加 @, 表示它是清單檔:

./bin/npseeker @target.list @control.list

例如 target.list 的內容可以是:

# 三個目標基因體
genomes/strain_A.fasta
genomes/strain_B.fna.gz
/data/others/strain_C.fa
  • 空白列與 # 開頭的列會略過, 可以拿來寫註解。
  • 相對路徑從執行指令時所在的資料夾算起, 不是從清單檔所在的資料夾算起。
  • 列出的檔案可以來自不同的資料夾, 也可以是 gzip (.gz) 或 zstd (.zst) 壓縮過的 FASTA 檔。
  • 給 -cluster-order input 時, 清單裡的順序就是分群時處理的順序 (第 4 章)。

沒有加 @ 的檔案若不是 FASTA 檔, 也會被當成清單檔讀; 加上 @ 可以避免誤會, 建議都加。

2.3 單一 FASTA 檔

目標或對照只有一個基因體時, 可以直接給那一個檔案 (壓縮過的也可以):

./bin/npseeker strain_A.fasta controls/

2.4 FASTA 檔的內容與檢查

  • 一個 FASTA 檔可以有好幾筆序列 (例如染色體與質體), 全部算同一個基因體。
  • 序列只看 A, C, G, T, 大小寫都可以。遇到其他字母 (例如 N) 時, 序列就在那裡斷開, 跨過它的 k-mer 不算。
  • 程式會先檢查每個輸入檔是不是 FASTA 格式; 找不到檔案或格式不對時, 會報錯並停止 (7.2 節)。
  • 同一個檔案不能同時當目標與對照; 程式發現時會列出重複的檔案並停止。

目標與對照怎麼選, 直接影響排名。對照最好包含實際應用時容易混淆的生物, 而不是隨意挑幾個其他物種。

3. 閱讀結果與挑選探針

3.1 畫面上的結果

沒有給 -o 時, 程式把前 -top 名 (預設 200) 的探針印在畫面上, 欄位有 Rank, Probe, 四項分數, Score 與 Tm。給了 -o 時, 完整的結果寫進檔案, 畫面上只列出存了哪些檔。加上 -v 可以另外看到設定與每個步驟花的時間。

3.2 結果檔

給 -o result/ 時, 預設存成 CSV 檔 (以逗號分隔各欄的文字檔):

cluster_N_probes.csv候選探針的排名; N 是群的編號, 從 0 開始
cluster.csv每個基因體屬於哪一群
flag.csv這一次計算用的設定

-format txt 改存成以空格對齊的表格, 方便直接閱讀; CSV 方便用試算表 (例如 Excel) 或其他程式處理。single 與 multi 模式存的檔案數不同, 見第 4 章。

cluster_N_probes.csv 各欄的意思:

Rank排名
Probe探針的序列 (從 5' 端寫到 3' 端)
Tgt在目標基因體裡出現的次數
Ctl在對照基因體裡出現 (一模一樣) 的次數; 越少越好
Exclus專一性分數, 由 Tgt 與 Ctl 算出
MMs對照裡只差幾個鹼基的相似序列的計分; 越少越好
Subseq探針的較短片段在對照裡出現的計分; 越少越好
Purity純度分數, 由 MMs 與 Subseq 算出
SelfAn自己摺起來 (self-annealing) 的程度; 越少越好
Dimer與另一條相同的探針黏在一起 (dimer) 的程度; 越少越好
UnFold不摺疊性分數, 由 SelfAn 與 Dimer 算出
Affini親和性分數, 由結合的自由能算出
Score四項分數的加權平均
Tm熔解溫度 (°C): 探針與目標結合的雙股有一半分開的溫度; 不算進總分

Exclus, Purity, UnFold, Affini 與 Score 都是 0 到 100, 越高越好。目標分成幾群時, Tgt 也會加上在其他群的目標裡只差幾個鹼基的相似序列, 所以不一定全是一模一樣的出現次數。

cluster.csv 有三欄: Group (target 或 control)、Cluster (目標屬於第幾群; 對照是空的) 與 File (檔名)。flag.csv 有兩欄: Option 與 Value, 可以用來確認這一次的設定。

輸出資料夾不存在時會自動建立; 已經存在但是空的, 也可以直接用。資料夾裡已經有東西時, 程式會報錯, 不會覆蓋。確定要覆蓋時加上 -w: 程式先刪掉資料夾裡之前的 NPSeeker 結果檔 (cluster_N_probes, cluster, flag), 其他檔案保留。覆蓋前請確定不再需要舊的結果。

3.3 怎麼挑探針

Score 可以當作初步的排名, 但不要只看總分。依用途還可以看:

  • Ctl: 大於 0 表示對照裡有一模一樣的序列, 探針可能也會黏到對照的生物 (交叉反應), 要特別留意。
  • Tgt: 次數多的探針, 訊號可能比較強, 但也可能落在重複的區域; 不能直接當作訊號強度。
  • Purity 與 UnFold: 用來比較黏錯地方與自己摺起來的風險。
  • Tm: 實驗有溫度的限制, 或同一次實驗要用好幾條探針時, 比較它們的 Tm; 同一次實驗用的探針, Tm 最好相近。

需要時, 再用 NCBI BLAST 查探針在其他物種裡有沒有相似的序列, 或用 UNAFold (mfold) 看它可能的摺疊結構。網頁介面的結果頁有這兩個連結, 但會把探針序列送到外部網站 (6.2 節)。探針是否適合某一個 BioFET 平台, 最後仍要依實際的實驗條件確認。

4. 目標分群與 single, multi 模式

所有目標共同的 k-mer 不夠時, NPSeeker 會把目標分成幾群。分群的方法是: 一個一個取基因體, 若它加入後, 這一群所有成員共同的 k-mer 仍有 -min-shared 個以上, 就加入這一群; 否則留給下一群。這些群是為了找候選而做的分組, 不代表演化或親緣上的分類。

-cluster-order 決定分群時取基因體的順序:

  • auto (預設): 依基因體彼此共有的 k-mer 決定順序; 輸入檔的排列不同, 同一組資料也會分出同樣的群。
  • input: 照輸入的順序 (清單檔列出的順序)。想讓某個參考基因體當第一群的核心時使用。

-min-shared 預設是 1, 表示加入後至少還有一個整群共有的 k-mer, 所以通常只有一群。調高時群數會變多, 每一群的候選也會跟著變。

分成幾群時, 用 -mode 決定探針怎麼輸出:

  • single (預設): 各群的候選合在一起排名, 只取總分的前 -top 名, 全部存在 cluster_0_probes.csv。排在前面的候選, 可能大多來自同一群。
  • multi: 各群分開排名, 各取前 -top 名, 存成 cluster_0_probes.csv, cluster_1_probes.csv 等。適合替不同的目標群各挑探針。

用 multi 從每一群各挑幾條, 合起來就是涵蓋所有目標群的一組探針; 但這是計算上的涵蓋, 實際偵測的效果仍要做實驗驗證。每一群有哪些基因體, 看 cluster.csv。某一群沒有探針通過過濾時, 程式會印出警告, 其他群的結果照樣存檔。

5. 選項與參數

選項寫在 target 與 control 後面。選項的值寫在選項後面, 中間空一格 (例如 -k 31); 開關 (例如 -v, -w, --gui) 不接值。有些選項有短名與長名 (例如 -k 與 -kmer), 兩者相同。數字可以寫成科學記號, 例如 1e7 是 10,000,000。以下依程式說明 (-help) 的分組說明, 各節標題後的括號是組名; 全部選項的一覽表在附錄 A。

5.1 探針長度與計算資源 (General settings)

-k, -kmer [整數, 5 到 256, 預設 25]

探針的長度 (鹼基數), 依實驗平台的需求設定。k 越長, 差異大的目標之間越不容易有完全相同的長序列, 可能要分成更多群。計算時間主要看資料與候選的多寡, k 增加不一定比較慢 (論文的 Figure 4)。

-t, -threads [整數, 預設 0]

同時計算的執行緒數。0 表示用上全部的處理器執行緒。與其他工作共用電腦時, 可以設少一點。

-m, -memory [大小, 預設為電腦記憶體的一半, 最多 8G]

主要計算步驟可以用的記憶體, 例如 -m 8G 或 -m 512M (沒寫單位時是 G)。給得少時, 程式會分批計算, 只是比較慢, 結果完全相同。讀入候選的批次 (-b) 與其他執行時需要的記憶體不算在內 (5.5 節)。

5.2 輸出與紀錄 (Output)

-o, -out-dir [資料夾, 預設不存檔]

結果檔存放的資料夾 (3.2 節)。沒有給時, 結果只印在畫面上, 欄位比較少。要留下結果, 日後分析、比較或重做計算, 建議給輸出資料夾。

-w, --overwrite

-o 的資料夾已經有東西時, 先刪掉裡面之前的 NPSeeker 結果檔, 再寫入新的; 其他檔案保留 (3.2 節)。

-top [整數, 預設 200]

每一群輸出幾條探針 (排名前幾名)。想多看一些候選時調高, 但數字太大會讓結果檔變大, 也可能用到更多記憶體與時間; 依實際需要設定。

-format [csv 或 txt, 預設 csv]

結果檔的格式: csv (以逗號分隔, 方便匯入試算表或給其他程式處理) 或 txt (以空格對齊的表格, 方便直接閱讀)。

-v, --verbose

詳細模式: 另外印出輸入、設定、每個計算步驟與它花的時間。追查問題, 或想知道大型計算進行到哪裡時很有用。從網頁介面開始的計算, 一律是詳細模式。

5.3 分群與排名 (Target clustering, Probe ranking)

-cluster-order [auto 或 input, 預設 auto]

分群時取目標基因體的順序。auto 不受輸入順序影響; input 照使用者給的順序。分群的方法與用途見第 4 章。

-min-shared [整數, 預設 1]

一群目標至少要共同擁有幾個 k-mer。調高時群數通常會變多, 但不保證每一群都找得到合適的探針 (第 4 章)。

-mode [single 或 multi, 預設 single]

只有分成幾群時才有差別: single 把各群的候選合在一起排名, multi 各群分開排名。怎麼選見第 4 章。

-weights [KEY=WEIGHT, 以逗號分隔, 預設四項都是 1]

調整專一性 (exc)、純度 (pur)、不摺疊性 (unf) 與親和性 (aff) 在總分裡的比重, 例如:

-weights exc=2,pur=2

表示專一性與純度各給兩倍的比重, 沒列出的 unf 與 aff 維持 1。總分這樣計算:

Score = (w_exc*Exclus + w_pur*Purity + w_unf*UnFold + w_aff*Affini)
        / (w_exc + w_pur + w_unf + w_aff)

權重可以是 0, 但不能是負數, 也不能全部是 0。權重是 0 的項目照樣計算, 只是不算進總分。加重某一項只是改變排名的比重, 不會把那一項分數低的候選剔除。

-mm, -mismatch-cutoff [整數, 預設為探針長度除以 10, 無條件捨去]

評純度時, 對照裡的序列與探針最多可以差幾個鹼基, 還算是相似序列。調高時會找到更多相似序列, 但比對的時間與記憶體可能大幅增加。必須小於探針長度。

5.4 候選過濾 (Candidate filtering)

候選先經過下面幾道過濾, 再做比較花時間的對照比對。門檻太嚴時, 可能一條探針都找不到; 這時可以逐一放寬下面的設定。

-max-homopolymer [整數, 預設 3]

同聚物 (homopolymer) 是同一種鹼基連成的一串, 例如 AAAA。這個選項是同聚物最長可以多長: 預設 3 表示 AAA 可以留下, 含有 AAAA 或更長一串的候選就去掉。調高會留下更多含長串相同鹼基的候選。

-c, -min-complexity [小數, 0 到 1, 預設 0.5]

序列複雜度的下限。四種鹼基用得越平均, 複雜度越高; 高於門檻的候選才留下。

-e, -min-entropy [小數, 0 到 2, 預設 1.5]

序列的熵 (entropy) 的下限。熵衡量序列有多「亂」: 一直重複同樣花樣的序列 (例如 ACACAC) 熵很低。高於門檻的候選才留下。探針短時, 複雜度與熵能達到的最高值也比較低; 設定的門檻超過這個長度能達到的最高值時, 程式會報錯, 並告訴您最高值是多少。

-prefilter [T 或 F, 預設 T]

要不要依不摺疊性先篩候選。T 先去掉不摺疊性低於 -min-unfold 的候選, 減少後面比對的量; F 不先篩, 但每個候選照樣計算不摺疊性分數。

-min-unfold [小數, 0 到 100, 預設 75]

先篩用的不摺疊性門檻。調低會留下更多容易摺疊的候選, 後面比對的量也可能增加。某一批候選全都低於門檻時, 程式會略過這一批的先篩。例如論文實驗用的陽性菌探針, 不摺疊性分數是 72.54; 要重現那個排名, 需要把 -min-unfold 調成 70 (第 8 章)。

5.5 進階選項 (Advanced)

一般使用時, 保留預設值即可。

-b, -batch-size [整數, 預設 1e7]

每次讀入、過濾的候選 k-mer 數。k = 25 時, 每個候選大約占 170 位元組, 預設的 1e7 (一千萬) 個候選大約需要 1.58 GiB, 不算在 -m 裡。電腦記憶體少時可以調低, 但批次變多, 時間也可能變長。

-s, -min-subseq [整數, 預設 7]

評純度時看的探針片段, 最短幾個鹼基; 與 -subseq-step 一起使用。

-subseq-step [整數, 預設為探針長度除以 10, 無條件進位]

評純度時, 片段長度每次減少多少。例如 k = 25 時預設是 3, 看長度 22, 19, 16, 13, 10, 7 的片段。數字越小, 看的片段長度越多, 比對的時間也越長。

-tmp-dir [資料夾, 預設為系統的暫存資料夾]

計算中間檔案的存放位置。NPSeeker 在這裡建立自己的暫存資料夾, 正常結束或按 Ctrl-C 中斷時會刪掉。系統磁碟的空間不夠時, 可以改到其他磁碟。

5.6 網頁介面與說明 (Graphical interface)

--gui在本機啟動網頁介面, 不直接在命令列計算
-gui-port [整數]介面使用的連接埠 (網址裡冒號後的數字), 預設由系統挑選
--no-browser只印出介面的網址, 不自動打開瀏覽器
--tab改在預設瀏覽器的分頁打開
-h簡短的說明
-help [KEYWORD]完整的說明, 或只看某個選項、某一組選項

--gui 只能與 -gui-port, --no-browser, --tab 一起用; 計算的參數 (例如 -k) 要在介面裡設定, 寫在命令列會報錯。網頁介面的細節見第 6 章。

6. 網頁介面

NPSeeker 在自己的電腦上開一個只有本機連得到的網頁伺服器 (網址是 127.0.0.1), 讓您用瀏覽器操作。計算仍由 NPSeeker 自己執行, 基因體不會上傳到外部網站。設定相同時, 網頁介面與命令列算出的結果完全相同。

6.1 啟動與連線

  • Windows: 在 bin 資料夾的 npseeker.exe 上雙按滑鼠左鍵, 或在命令提示字元執行 .\bin\npseeker.exe --gui。程式會開一個黑色的主控台視窗 (印出程式訊息的文字視窗); 使用介面期間, 請讓它保持開啟。
  • macOS, Linux: 在終端機執行 ./bin/npseeker --gui。

程式會自動打開瀏覽器, 並印出介面的網址, 例如:

http://127.0.0.1:53817/?t=1a2b3c...

網址裡 ?t= 後面是這一次的存取碼。瀏覽器沒有自動打開時, 把完整的網址複製到瀏覽器即可。網址裡有存取碼, 不要隨意轉傳給別人。

介面預設開在獨立的視窗: Edge, Chrome 這類瀏覽器會開成沒有網址列的應用程式視窗, Firefox 則開新視窗。加上 --tab 改在預設瀏覽器的分頁打開。

6.2 主要頁面

Design選擇 Target, Control, 輸出資料夾與探針長度。可以直接選資料夾, 也可以勾選檔案, 把不同位置的 FASTA 檔 (含壓縮檔) 加進來。"Tick all" 勾選資料夾裡的全部檔案; "Pick folder", "Pick files" 用作業系統的選擇視窗。其他設定可以展開來看, 空白的欄位表示用預設值。"Check" 只檢查輸入與設定, "Go" 開始計算。
Run顯示目前的步驟、進度與執行紀錄。"Cancel" 中止計算。
Results看排名、探針序列與各項分數。按欄名可以排序, Rank 仍是原本的排名。按探針可以看它的反向互補序列與熔解溫度, 也可以複製。結果檔可以一個一個下載, 也可以打包成一個 zip 檔下載。
Help閱讀使用說明, 可以切換語言 (會記住上次選的; 預設英文)。
About程式、論文、作者與聯絡資訊。

Results 頁另有兩個外部網站的連結:

  • BLAST at NCBI: 用選取的探針序列打開 NCBI BLAST, 查其他物種裡有沒有相似的序列。
  • Fold at UNAFold: 把序列送到 UNAFold (mfold) 預測 DNA 的摺疊; 用該網站表單的預設條件 (37 °C, 1 M Na+)。

這兩個功能需要網路, 而且會把選取的探針序列送到外部網站。序列還沒公開時, 請先確定可以使用外部服務。

沒有指定輸出資料夾時, 網頁介面把結果暫存在系統磁碟; 介面結束後, 暫存的結果會刪掉。要留下結果, 請在結束介面前下載。

6.3 Close, Exit 與結果的保存

  • "Close" 只關掉瀏覽器的頁面, NPSeeker 繼續執行。需要時, 再打開主控台印出的網址, 就能回到介面。
  • "Exit" 結束介面, 並中止進行中的計算。關掉主控台視窗或按 Ctrl-C 也會結束。
  • 所有介面頁面都關掉超過 5 分鐘, 而且沒有計算在進行時, 程式會自動結束; 還沒下載的暫存結果也會一起刪掉。

按 "Exit" 或 "Close" 時, 介面會先問一次; 計算還在進行, 或有還沒下載的暫存結果時, 會一併列出來提醒。

有指定輸出資料夾時, 結果存在那裡。再次用同一個資料夾時, 會取代之前的 NPSeeker 結果檔, 其他檔案保留。

介面的顏色可以切換 Auto, Dark, Light。Auto 跟著作業系統的深色或淺色設定。

6.4 在遠端伺服器上操作

NPSeeker 裝在遠端的伺服器上時, 可以透過 SSH 通道 (把本機的連接埠轉到伺服器上的加密連線), 在自己電腦的瀏覽器操作。先在伺服器上啟動程式, 並指定連接埠:

./bin/npseeker --gui --no-browser -gui-port 53817

再從自己的電腦打開終端機, 建立 SSH 通道:

ssh -L 53817:127.0.0.1:53817 帳號@伺服器

SSH 連線保持開啟時, 在自己電腦的瀏覽器輸入伺服器印出的完整網址。本機的連接埠也可以換成別的數字, 例如 ssh -L 9000:127.0.0.1:53817; 這時網址要改成 http://127.0.0.1:9000/, 後面保留原本的 ?t= 存取碼。

遠端使用時, 介面看到的是伺服器上的檔案。"Pick folder", "Pick files" 的選擇視窗也會開在伺服器上, 伺服器沒有圖形桌面時用不了; 這時請用介面裡的檔案瀏覽功能。

6.5 設定檔的位置

程式會記住最近用過的資料夾 (recent.txt)、上次選擇的位置 (lastpick.txt)、介面的配色 (theme.txt) 與 Help 頁的語言 (help-lang.txt), 下次使用時比較方便。這幾個小檔案放在:

Linux~/.config/npseeker/
macOS~/Library/Application Support/npseeker/
Windows%AppData%\npseeker\

計算中間檔案放在系統的暫存資料夾, 或 -tmp-dir 指定的位置, 不在這裡。

7. 效能與問題排除

7.1 記憶體、時間與暫存檔

  • 記憶體: -m 管主要計算步驟的記憶體, 但 -b 讀入的候選與其他執行時的資料也要用記憶體。記憶體不夠時, 可以把 -m 與 -b 都調低。
  • 執行緒: -t 0 用上全部的處理器執行緒。與其他工作共用電腦時, 可以設少一點。
  • 時間: 受基因體大小、共同候選的多寡、-mm、記憶體、硬體與磁碟速度影響。k 增加不一定比較慢; 加 -v 可以看每個步驟花的時間。
  • 暫存檔: 計算時會產生暫存檔, 大小看資料與記憶體而定 (記憶體給得少時, 暫存檔比較多)。請留足夠的磁碟空間; 正常結束或按 Ctrl-C 中斷時, 暫存檔會刪掉。

7.2 常見的錯誤訊息

選項或參數寫錯時, 訊息以 npseeker: 開頭; 輸入、輸出或執行時出錯, 訊息以 Error: 開頭。下面是常見的例子與處理方法 (target 也可能是 control, 表示出問題的是對照):

  • Error: target: no FASTA file (*.fasta, *.fna or *.fa) in the folder ...
    資料夾裡沒有這三種副檔名的檔案。壓縮檔請改用清單檔 (2.2 節)。
  • Error: target: "..." is not found
    路徑寫錯, 或相對路徑不是從目前的資料夾算起。
  • Error: target: "..." is not a FASTA file: ...
    檔案不是 FASTA 格式; 冒號後面寫了檢查到的問題。
  • Error: target: the FASTA file "...", listed in "...", is not found
    清單檔列出的檔案有一個找不到。
  • Error: target and control: ...; a genome cannot be both a target and a control
    同一個檔案同時出現在目標與對照。
  • Error: -o: the folder "..." already exists and is not empty; give -w ...
    輸出資料夾裡已經有東西。請換一個資料夾, 或確定可以覆蓋後加 -w。
  • npseeker: option -mm: must be less than the probe length (-k)
    -mm 要小於探針長度。
  • npseeker: option -c: no probe of 8 nt has a complexity score above 0.431 ...
    門檻超過這個探針長度能達到的最高值 (這裡是 0.431); 請調低 (5.4 節)。
  • Error: -tmp-dir: cannot create the folder "...": ...
    無法建立暫存資料夾; 請檢查路徑與寫入權限。

7.3 畫面上的兩種訊息

畫面上的訊息其實走兩個管道: 標準輸出 (stdout) 與標準錯誤 (stderr)。平常兩者都顯示在畫面上, 看不出差別; 只有把輸出存成檔案時 (例如在指令最後加 > out.txt) 才分得出來: 存進檔案的只有標準輸出, 標準錯誤仍然顯示在畫面上。

NPSeeker 把計算的結果、-v 的執行紀錄與錯誤訊息寫到標準輸出; 開頭是 Note: 或 Warning: 的提醒與警告, 以及進度條, 寫到標準錯誤。所以把輸出存成檔案時, 檔案裡是乾淨的結果, 提醒與進度仍然看得到。

7.4 沒有候選探針或執行很慢

沒有任何候選通過過濾時, 程式會印出:

Warning: no probe passed the filters; relax the thresholds
         (-max-homopolymer, -c, -e, -min-unfold) to let probes pass.

可以依序放寬 -min-unfold, -c, -e 與 -max-homopolymer (5.4 節)。如果各目標共同的 k-mer 本來就很少, 可以試著縮短 -k, 或調整 -min-shared 與 -mode (第 4 章)。加 -v 可以看每個步驟留下多少候選、花了多少時間。

計算很慢時, 先確認 -m 加上 -b 需要的記憶體沒有超過電腦可用的記憶體; 超過時, 系統會把記憶體的內容搬到磁碟上暫放, 速度會慢很多。-mm 設得很高時, 可以先改回預設值比較看看。資料集很大時, 也要留意磁碟的速度與暫存資料夾的空間。

8. 常用範例

下面的範例用 macOS 與 Linux 的寫法。Windows 請把 ./bin/npseeker 換成 .\bin\npseeker.exe, 路徑裡的 / 換成 \。每個範例都可以單獨執行; result/ 已經有之前的結果時, 請換一個輸出資料夾, 或確定可以覆蓋後加上 -w。

基本的計算, 結果存到 result/:

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

用清單檔指定目標, 並照清單的順序分群:

./bin/npseeker @target.list controls/ -cluster-order input -o result/

設計長度 31 的探針, 用 32 個執行緒與 16 GiB 的記憶體:

./bin/npseeker targets/ controls/ -k 31 -t 32 -m 16G -o result/

加重專一性與純度在總分裡的比重:

./bin/npseeker targets/ controls/ -weights exc=2,pur=2 -o result/

替幾個目標群分別找候選探針:

./bin/npseeker targets/ controls/ -min-shared 20000 -mode multi -o result/

重現論文 Table 3 的細菌探針排名 (用研究時的參數, 不是全部用預設值; 資料集要另外下載, 放法見 0.2 節):

./bin/npseeker dat/datasets/GP/ dat/datasets/GN/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GP_probes/
./bin/npseeker dat/datasets/GN/ dat/datasets/GP/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GN_probes/

其中 -min-unfold 70 是為了留下不摺疊性分數 72.54 的實驗用陽性菌探針。上面的指令在 macOS 與 Linux 用 \ 接到下一列; Windows 的命令提示字元改用 ^, PowerShell 改用反引號 `, 或全部寫成同一列。

論文的資料集有一部分取自 ATCC 的基因體資料庫 (ATCC Genome Portal), ATCC 的使用條款不允許轉散布, 所以 dat/datasets/ 附的是 NCBI 上的對應資料, 兩者的逐檔對照見 dat/datasets/sources.txt。用這份資料, Table 3 兩條探針的序列與排名都與論文相同, 但候選的總數、出現次數與各項分數會略有不同。其中 S. enterica ATCC 43976 在 NCBI 只有不完整的組裝 (缺了 23S rRNA 的一段)。以 GN 為目標時不選這個基因體 (網頁介面裡取消勾選; 命令列改用清單檔 @dat/datasets/GN-without-43976.list), 候選數就會恢復為 65, 補充資料 Table S3 的前 8 名也與論文相同。

改存成方便閱讀的表格, 並多輸出一些探針:

./bin/npseeker targets/ controls/ -format txt -top 1000 -o result/
