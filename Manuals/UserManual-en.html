NPSeeker User Manual

Version 1.5.42

About NPSeeker

NPSeeker (Nucleic Acid Probe Seeker) is a program for designing nucleic acid probes from genome sequences. It is intended primarily for selecting probes for biosensors such as BioFETs (biological field-effect transistors). A nucleic acid probe is a short DNA sequence that binds to DNA from an organism of interest, allowing that organism to be detected or identified.

NPSeeker takes two groups of genomes: targets (the organisms to detect) and controls (the organisms that should not be detected). It first finds DNA sequences shared by all target genomes. It then evaluates how closely these sequences resemble the controls, how strongly they bind to their targets, and whether they are likely to fold back on themselves. The candidate probes are ranked by their scores. Probe length is adjustable from 5 to 256 nucleotides.

0. Quick Start

Commands in this manual use macOS and Linux syntax unless otherwise noted. Windows commands are provided where they differ.

If you have never used a command-line program, follow this chapter in order.

0.1 Download the Right Version

Download the archive for your operating system from the NPSeeker website or GitHub. Separate archives are available for Windows, macOS, and Linux. Each archive contains executables for two processor architectures:

x86_64Most Intel and AMD processors
arm64Macs with Apple M-series chips and other ARM-based computers

If you are not sure which architecture your computer uses:

  • Windows: Open "Settings -> System -> About". Under "System type", x64 means x86_64 and ARM64 means arm64.
  • macOS: Open "Apple menu -> About This Mac". A Mac with an Apple M-series chip uses arm64; a Mac with an Intel processor uses x86_64.
  • Linux: Open a terminal, type uname -m, and press Enter. The output is x86_64 or aarch64 (which means arm64).

0.2 Extract the Archive

Extract the downloaded archive to any folder:

  • Windows: Right-click the archive and select "Extract All".
  • macOS: Double-click the archive.
  • Linux: In a terminal, run tar xzf followed by the archive filename.

The extracted NPSeeker folder contains:

bin/x86_64 executable: npseeker (npseeker.exe on Windows)
bin.arm64/arm64 executable
doc/User manuals
dat/sample/Example data for your first run

The bacterial genomes used in the NPSeeker paper (Gram-negative GN and Gram-positive GP) are a separate download (NPSeeker-1.5.42-datasets.zip or .tar.gz). You may extract it and move the datasets folder it contains (under NPSeeker/dat/) into the program's dat folder, so that you can run the command examples in Chapter 8 as written.

NPSeeker does not require installation or an internet connection for local analysis. Commands in this manual use the x86_64 executable in bin/. On an arm64 computer, replace bin with bin.arm64 in the commands.

0.3 Check That NPSeeker Runs

Open a command-line window and change to the extracted NPSeeker folder:

  • Windows: Open the NPSeeker folder in File Explorer. Type cmd in its address bar and press Enter. A Command Prompt opens in that folder. You can also use PowerShell with the same commands.
  • macOS: Open "Terminal" (Applications -> Utilities). Type cd followed by a space, drag the NPSeeker folder into the Terminal window, and press Enter.
  • Linux: Open a terminal and use cd to change to the NPSeeker folder.

Then enter the appropriate command and press Enter:

Windows:          .\bin\npseeker.exe -h
macOS, Linux:     ./bin/npseeker -h

If the program displays its logo, usage information, and common options, it is ready to use.

An unsigned program downloaded from the internet may trigger an operating-system security warning when first launched.

Before allowing the program to run, make sure you downloaded it from the NPSeeker website or GitHub listed under "About NPSeeker". Do not bypass security warnings for software from an unknown source.

  • Windows: A blue "Windows protected your PC" window may appear, with a Microsoft Defender SmartScreen message and only a "Don't run" button. Click "More info" below the message. The window will show the application name and "Publisher: Unknown publisher", along with a "Run anyway" button. Click "Run anyway" to launch NPSeeker. This prompt normally appears only once for the same executable.
  • macOS: The system may block an application that has not been notarized by Apple. In Terminal, run xattr -dr com.apple.quarantine followed by the path to the NPSeeker folder (you can drag the folder into Terminal to insert its path). Alternatively, try launching NPSeeker once, then open "System Settings -> Privacy & Security" and select "Open Anyway" for npseeker.
  • Linux: This extra step is normally unnecessary. If you see "permission denied", run chmod +x bin/npseeker (or chmod +x bin.arm64/npseeker for arm64) and try again.

0.4 Run Your First Analysis in the Graphical Interface

If you would rather not use the command line, NPSeeker also has a browser-based interface. On Windows, double-click npseeker.exe in bin/. On macOS or Linux, enter this command in a terminal:

./bin/npseeker --gui

The interface opens in your browser. To try it with the included example data, go to the Design page:

  • Target: Select dat/sample/S.aureus/, which contains a genome of the bacterium Staphylococcus aureus.
  • Control: Select dat/sample/yeast/, which contains genomes from two yeast species.
  • Probe length: Leave the default value of 25 and keep the other settings unchanged.
  • Click "Check" to validate the inputs and settings, then click "Go" to start the analysis.
  • When the run finishes, open the Results page to inspect the ranked probes and their scores. Download any results you want to keep.

The graphical interface runs on your own computer; it does not send your genome files to an external website. See Chapter 6 for a description of the interface and how to close it.

0.5 Run Your First Analysis from the Command Line

You can analyze the same example data directly from the command line:

Windows:          .\bin\npseeker.exe dat\sample\S.aureus\ dat\sample\yeast\
macOS, Linux:     ./bin/npseeker     dat/sample/S.aureus/ dat/sample/yeast/

The run should finish within a few seconds. The screen shows a ranked list of probes, such as the excerpt below:

Best probes of cluster 0:

   1 CCGACTAACCCAGAGCGGACGAGCC  50.84  61.32 100.00  64.22  69.10  65.88
   2 GACCCGACTAACCCAGAGCGGACGA  50.84  61.40 100.00  63.68  68.98  64.24

Each row represents a candidate probe. Probe is its DNA sequence; Score is its overall score, with higher-scoring probes listed first. Chapter 3 explains the other columns. A Note at the end reminds you to use -o if you want to save the full results to files. For example:

The result files will be written to result/ (Section 3.2). If you run NPSeeker again, choose a new output folder or add -w only if you are willing to replace the previous results. To analyze your own genomes, replace the two example folders with your target and control inputs (Chapter 2).

1. How NPSeeker Designs and Scores Probes

NPSeeker takes target and control genomes as input and produces ranked candidate probes. Targets are organisms you want to detect, while controls are organisms you want the probes to avoid, often closely related species that could be mistaken for the targets. The analysis has four main steps:

  • Find shared sequences: NPSeeker scans each genome for every consecutive stretch of k nucleotides, called a k-mer. For example, the 3-mers of ACGTA are ACG, CGT, and GTA. Every k-mer present in all target genomes becomes a candidate probe. To detect every target using a single probe, the probe's sequence must be shared by all of them. DNA has two complementary strands, so NPSeeker treats each k-mer and its reverse complement as the same k-mer.
  • Filter candidates: NPSeeker removes sequences that are unsuitable as probes, such as those with unbalanced nucleotide composition, long runs of one base (e.g., AAAA), or a tendency to fold back on themselves or pair with other copies of the same probe. Filtering avoids spending time on poor candidates in later steps.
  • Check the controls: For each remaining candidate, NPSeeker searches the control genomes for exact matches, near matches differing by only a few bases, and occurrences of shorter probe fragments.
  • Score and rank: NPSeeker calculates four scores for each candidate and combines them into an overall score.
ExclusivityOccurs in the targets but rarely in the controls
PurityFew similar sequences or shorter matching fragments in controls, reducing the risk of unintended binding
UnfoldabilityLow tendency to fold back on itself, leaving the probe accessible for binding to its target
AffinityPredicted binding strength, from the free energy of binding (the energy released when the probe binds to its target)

Each component and the overall score range from 0 to 100, with higher scores indicating more favorable predicted properties. By default, all four components have equal weight. These scores help prioritize candidates for experimental validation; they are not measured BioFET signal strengths and do not guarantee performance in an experiment.

If the target genomes are too different to share enough k-mers, NPSeeker divides them into groups and finds candidates separately for each group. See Chapter 4 for clustering and output modes, or the research paper for scoring equations and algorithmic details.

2. Preparing Target and Control Genomes

The first two command-line arguments specify the target and control inputs, in that order. Options come afterward:

./bin/npseeker <target> <control> [options]

Prepare one FASTA file per genome. FASTA is a plain-text format for DNA sequences, usually with a .fasta, .fna, or .fa filename extension. You can specify targets and controls independently as folders, file lists, or individual FASTA files.

2.1 Folder Input

When given a folder, NPSeeker reads files ending in .fasta, .fna, or .fa and treats each file as one genome. Extensions can be entirely lowercase or entirely uppercase (e.g., .FASTA). Subfolders are not searched.

./bin/npseeker targets/ controls/

Compressed files (.gz, .zst) inside a folder are not included. To use compressed FASTA files, specify them through a file list instead.

2.2 File Lists

A file list is a plain-text file containing one FASTA file path per line. Prefix the list filename with @ to tell NPSeeker to read it as a list:

./bin/npseeker @target.list @control.list

For example, target.list could contain:

# Three target genomes
genomes/strain_A.fasta
genomes/strain_B.fna.gz
/data/others/strain_C.fa
  • Empty lines and lines beginning with # are ignored, so you can use them for comments.
  • Relative paths are resolved from the directory where you run NPSeeker, not from the directory containing the list.
  • The listed files may come from different folders and may be gzip (.gz) or zstd (.zst) compressed FASTA files.
  • With -cluster-order input, the order of the files in the list determines their processing order during clustering (Chapter 4).

A non-FASTA file supplied without @ is also interpreted as a file list. Adding @ makes your intention explicit and is recommended.

2.3 Single FASTA File

If a target or control group contains only one genome, you can give NPSeeker the FASTA file directly. Compressed FASTA files are also supported:

./bin/npseeker strain_A.fasta controls/

2.4 FASTA Contents and Input Checks

  • A FASTA file may contain multiple sequence records, such as chromosomes and plasmids. All records in the file are treated as one genome.
  • NPSeeker accepts A, C, G, and T in either case. Other letters, such as N, interrupt the sequence; k-mers spanning those positions are excluded.
  • NPSeeker checks the input files for FASTA format and stops with an error if a file is missing or invalid (Section 7.2).
  • The same file cannot appear in both target and control inputs. If it does, NPSeeker reports the duplicate and stops.

Your choice of target and control genomes directly affects the probe ranking. Controls should include organisms that might realistically be confused with your targets, rather than an arbitrary selection of unrelated species.

3. Understanding Results and Selecting Probes

3.1 Results on the Screen

Without -o, NPSeeker prints the top -top probes (200 by default) to the screen, showing Rank, Probe, the four component scores, Score, and Tm. With -o, it writes the detailed results to files and lists the saved files on the screen instead. Add -v to see the settings and the time spent in each processing step.

3.2 Output Files

For example, -o result/ saves the results as CSV (comma-separated values) files by default:

cluster_N_probes.csvRanked candidate probes; N is the cluster number, starting from 0
cluster.csvCluster assignment for each genome
flag.csvSettings used for this run

Use -format txt for space-aligned, human-readable tables. CSV files are convenient for spreadsheets such as Excel or for other programs. The number of probe files depends on whether you use single or multi mode (Chapter 4).

The columns in cluster_N_probes.csv are:

RankProbe rank
ProbeProbe sequence, written 5' to 3'
TgtOccurrences in the target genomes
CtlExact occurrences in the control genomes; fewer is better
ExclusExclusivity score, calculated from Tgt and Ctl
MMsScore for near matches in the controls; lower is better
SubseqScore for shorter probe fragments found in the controls; lower is better
PurityPurity score, calculated from MMs and Subseq
SelfAnTendency to fold back on itself (self-annealing); lower is better
DimerTendency to pair with another copy (dimer); lower is better
UnFoldUnfoldability score, calculated from SelfAn and Dimer
AffiniAffinity score, based on binding free energy
ScoreWeighted average of the four component scores
TmMelting temperature (°C), at which half of the probe-target duplexes are separated; not part of Score

Exclus, Purity, UnFold, Affini, and Score range from 0 to 100; higher is better. When targets are split into multiple clusters, Tgt also includes near matches in target genomes outside the candidate's own cluster. It therefore does not always represent only exact occurrences.

The cluster.csv file contains three columns: Group (target or control), Cluster (the cluster number for a target, blank for a control), and File (filename). The flag.csv file contains Option and Value, allowing you to check the settings used for the run.

If the output folder does not exist, NPSeeker creates it. An existing empty folder is also accepted. If the folder already contains files, NPSeeker stops rather than overwriting them. Add -w only when you intend to replace earlier results: NPSeeker deletes previous NPSeeker result files (cluster_N_probes, cluster, and flag) but leaves unrelated files untouched. Make sure you no longer need the old results before using -w.

3.3 Choosing Probes

Score provides a useful starting point, but probe selection should not rely on the overall score alone. Depending on your application, also consider:

  • Ctl: A value greater than zero means an identical sequence occurs in a control genome. The probe might therefore bind to a non-target organism (cross-reactivity).
  • Tgt: More occurrences may lead to a stronger signal, but they may also indicate a repetitive region. Tgt is not a direct prediction of signal strength.
  • Purity and UnFold: These help compare the risks of unintended binding and of the probe folding back on itself.
  • Tm: If an assay has temperature constraints or uses several probes together, compare their melting temperatures. Probes used in the same assay should preferably have similar Tm values.

You may also check a probe with NCBI BLAST for similar sequences in other organisms or use UNAFold (mfold) to examine possible folding structures. Links to both services are available on the Results page, but they send the selected probe sequence to an external website (Section 6.2). Ultimately, whether a probe works well on a particular BioFET platform must be established under the intended experimental conditions.

4. Target Clustering and the single/multi Modes

When too few k-mers are shared by all target genomes, NPSeeker divides the targets into clusters. It processes the genomes one at a time. A genome is added to the current cluster only if the number of k-mers shared by every member of that cluster, including the new genome, remains at least -min-shared. Otherwise, that genome is deferred to another cluster. These clusters are computational groups for candidate discovery, not evolutionary or phylogenetic classifications.

The -cluster-order option controls the order in which target genomes are considered:

  • auto (default): Uses k-mer similarity among genomes to choose a deterministic order. Changing the order of input files does not change the clusters for the same set of genomes.
  • input: Uses the user-supplied order (for example, the order in a file list). Choose this if you want a particular reference genome to serve as the starting point for the first cluster.

The default -min-shared is 1: a genome may join as long as at least one k-mer remains shared by the entire cluster, so the targets will often form a single cluster. Increasing this value can produce more clusters and change the candidates available in each one.

If there is more than one target cluster, -mode determines how the candidates are ranked and saved:

  • single (default): Combines candidates from all clusters into one ranking and retains only the overall top -top probes in cluster_0_probes.csv. Many of the highest-ranked candidates may come from the same cluster.
  • multi: Ranks each cluster separately and retains up to -top probes per cluster in cluster_0_probes.csv, cluster_1_probes.csv, and so on. Use this mode when you want candidates for each target cluster.

In multi mode, selecting probes from each cluster gives a set of candidates that computationally covers all target clusters. Actual detection performance still requires experimental validation. Check cluster.csv to see which genomes belong to each cluster. If no candidate from a cluster passes filtering, NPSeeker reports a warning while saving the results of the other clusters.

5. Options and Parameters

Place options after the target and control inputs. An option that takes a value is followed by a space and that value (for example, -k 31). Switches such as -v, -w, and --gui take no value. Some options have short and long forms (for example, -k and -kmer); either form works. Numeric values may use scientific notation: 1e7 means 10,000,000. The sections below follow the sections of the program's -help output; the name in parentheses after each heading is the -help section name. Appendix A provides a quick reference.

5.1 Probe Length and Computing Resources (General settings)

-k, -kmer [integer, 5 to 256; default: 25]

Sets the probe length in nucleotides. Choose a length appropriate for your assay. As k increases, divergent target genomes become less likely to share identical sequences of that length, and additional clusters may be needed. Running time depends mainly on genome sizes and the number of candidates: longer probes are not necessarily slower (see Figure 4 in the paper).

-t, -threads [integer; default: 0]

Sets the number of worker threads. A value of 0 uses all available hardware threads. Reduce it if the computer needs to remain available for other tasks.

-m, -memory [size; default: half of physical memory, capped at 8G]

Sets the memory budget for the main computational steps, such as -m 8G or -m 512M. A value without a unit is interpreted in GiB. A smaller budget causes more batch processing and may slow the analysis, but does not change the results. Memory used to load candidate batches (-b) and other runtime data is additional to this budget (Section 5.5).

5.2 Output and Logging (Output)

-o, -out-dir [folder; default: do not save results]

Specifies where the result files will be saved (Section 3.2). Without -o, results are printed to the screen with fewer columns. Use an output folder if you want to retain, compare, or reproduce the analysis later.

-w, --overwrite

Allows NPSeeker to reuse a nonempty -o folder. Previous NPSeeker result files in that folder are removed before new ones are written; other files are preserved (Section 3.2).

-top [integer; default: 200]

Sets how many top-ranked probes to output for each ranking. Increase it if you want to inspect more candidates. Very large values produce larger output files and may require more memory and time, so choose a value appropriate for your needs.

-format [csv or txt; default: csv]

Controls the output format. csv uses comma-separated values suitable for spreadsheets or other programs; txt produces a space-aligned table for reading directly.

-v, --verbose

Shows additional details, including the inputs, settings, processing steps, and time spent in each step. Useful for troubleshooting or monitoring a large run. Analyses started from the graphical interface always use verbose logging.

5.3 Clustering and Ranking (Target clustering, Probe ranking)

-cluster-order [auto or input; default: auto]

Sets the order in which target genomes are processed for clustering. auto is independent of the order of the input files; input follows the supplied order. See Chapter 4 for details and use cases.

-min-shared [integer; default: 1]

Sets the minimum number of k-mers that must remain common to all genomes in a cluster. Increasing this threshold generally produces more clusters, but it does not guarantee that every cluster will yield suitable probes (Chapter 4).

-mode [single or multi; default: single]

These modes differ only when targets form multiple clusters. single ranks candidates from all clusters together; multi generates a separate ranking for each cluster. See Chapter 4 to choose the appropriate mode.

-weights [comma-separated KEY=WEIGHT; default: 1 for each component]

Adjusts the contributions of exclusivity (exc), purity (pur), unfoldability (unf), and affinity (aff) to the overall score. For example:

-weights exc=2,pur=2

This assigns twice as much weight to exclusivity and purity while leaving unf and aff at 1. The overall score is calculated as:

Score = (w_exc*Exclus + w_pur*Purity + w_unf*UnFold + w_aff*Affini)
        / (w_exc + w_pur + w_unf + w_aff)

Weights may be zero but not negative, and at least one must be positive. A component with zero weight is still calculated; it simply does not contribute to Score. Increasing a weight changes the ranking, but does not filter out candidates with low scores for that component.

-mm, -mismatch-cutoff [integer; default: floor(probe length / 10)]

Sets the maximum number of nucleotide differences allowed when finding near matches to a probe in the control genomes for purity scoring. A larger cutoff can reveal more near matches, but may substantially increase computation time and memory use. The cutoff must be smaller than the probe length.

5.4 Candidate Filtering (Candidate filtering)

NPSeeker filters candidates before the more expensive comparison against control genomes. If the criteria are too strict, no candidates may remain. You can then relax one or more of the following thresholds.

-max-homopolymer [integer; default: 3]

A homopolymer is a run of identical nucleotides, such as AAAA. This option sets the longest permitted run: the default of 3 allows AAA but rejects a candidate containing AAAA or a longer run. Increasing the limit retains more candidates with repeated bases.

-c, -min-complexity [number, 0 to 1; default: 0.5]

Sets the minimum sequence-complexity score. Sequences with a more balanced mix of the four nucleotides have higher scores. A candidate must score above the threshold to pass.

-e, -min-entropy [number, 0 to 2; default: 1.5]

Sets the minimum sequence-entropy score. Entropy measures how varied a sequence is: repetitive patterns such as ACACAC have low entropy. A candidate must score above the threshold to pass. Shorter probes have lower maximum possible complexity and entropy scores. If a specified threshold exceeds the maximum possible score for the selected length, NPSeeker reports an error and tells you the maximum.

-prefilter [T or F; default: T]

Controls whether candidates are filtered by unfoldability before scanning the controls. T removes candidates below -min-unfold, reducing the number of comparisons. F skips this early filter, but the unfoldability score is still calculated for each candidate.

-min-unfold [number, 0 to 100; default: 75]

Sets the unfoldability threshold used by the early filter. Lowering it retains more candidates that may fold back on themselves, potentially increasing the amount of later comparison work. If none of the candidates in a batch meet the threshold, NPSeeker skips the prefilter for that batch. For example, the experimentally tested Gram-positive probe in the paper has an unfoldability score of 72.54; use -min-unfold 70 to reproduce its ranking (Chapter 8).

5.5 Advanced Options (Advanced)

The defaults are suitable for most uses.

-b, -batch-size [integer; default: 1e7]

Sets how many candidate k-mers are loaded and filtered at a time. At k = 25, each candidate uses approximately 170 bytes, so the default batch of 10 million candidates requires about 1.58 GiB, in addition to the memory budget set by -m. Reduce this setting on computers with limited memory; smaller batches may increase running time.

-s, -min-subseq [integer; default: 7]

Sets the shortest probe-fragment length considered in purity scoring. Used together with -subseq-step.

-subseq-step [integer; default: ceiling(probe length / 10)]

Sets how much the fragment length decreases at each step during purity scoring. For example, with k = 25 the default step is 3, so fragment lengths are 22, 19, 16, 13, 10, and 7. A smaller step considers more fragment lengths and increases the comparison workload.

-tmp-dir [folder; default: system temporary folder]

Sets the location for intermediate files. NPSeeker creates its own subfolder there and removes it when the run finishes normally or is interrupted with Ctrl-C. Use a folder on another disk if the system disk lacks sufficient free space.

6. Graphical Interface

NPSeeker runs a small web server on your computer, accessible only from that computer (127.0.0.1), and uses a browser as its interface. NPSeeker itself performs the analysis; your genome files are not uploaded to an external website. With the same settings, the graphical interface and command line produce identical results.

6.1 Starting and Connecting

  • Windows: Double-click npseeker.exe in bin/, or run .\bin\npseeker.exe --gui from Command Prompt. The program opens a console window (a black text window displaying program messages). Keep that window open while using the interface.
  • macOS, Linux: Run ./bin/npseeker --gui in a terminal.

NPSeeker normally opens your browser automatically and also prints the interface URL, for example:

http://127.0.0.1:53817/?t=1a2b3c...

The part after ?t= is an access token for the current session. If the browser does not open automatically, copy the entire URL into your browser. Because the URL contains an access token, do not share it unnecessarily.

By default, the interface opens in a separate window. Browsers such as Edge and Chrome use an application-style window without an address bar; Firefox opens a new window. Use --tab to open the interface in a tab of your default browser instead.

6.2 Main Pages

DesignSelect the Target and Control genomes, an optional output folder, and the probe length. Choose folders or select individual FASTA files, including compressed files from different locations. "Tick all" selects all files in a folder; "Pick folder" and "Pick files" open the operating system's file chooser. Expand the additional settings when needed; blank fields use their defaults. "Check" validates inputs and settings, while "Go" starts the analysis.
RunView the current step, progress, and execution log. "Cancel" stops the analysis.
ResultsBrowse ranked probes, sequences, and component scores. Click a column heading to sort; Rank retains the original NPSeeker ranking. Click a probe to inspect its reverse complement and melting temperature or to copy the sequence. Download result files individually or together as a zip archive.
HelpRead the user manual and switch languages (English by default; your last choice is remembered).
AboutView program, publication, author, and contact information.

The Results page also offers links to two external services:

  • BLAST at NCBI: Opens NCBI BLAST with the selected probe sequence so you can look for similar sequences in other organisms.
  • Fold at UNAFold: Sends the sequence to UNAFold (mfold) for DNA folding prediction, using the website's default form settings (37 °C, 1 M Na+).

These two services require an internet connection and transmit the selected probe sequence to an external website. Before using them with unpublished sequences, make sure sharing the sequence is appropriate.

If you do not specify an output folder, the graphical interface stores the results temporarily on the local disk. These temporary results are deleted when the interface exits. Download any files you wish to keep before leaving.

6.3 Close, Exit, and Saved Results

  • "Close" closes only the browser page; NPSeeker keeps running. To return to the interface, reopen the URL printed in the console.
  • "Exit" shuts down the interface and stops any analysis still running. Closing the console window or pressing Ctrl-C also exits the program.
  • If all interface pages remain closed for more than five minutes and no analysis is running, NPSeeker exits automatically. Any results still in temporary storage are deleted at that point.

The interface asks for confirmation when you click "Exit" or "Close" and warns you if an analysis is still running or temporary results have not yet been downloaded.

If you specified an output folder, the results remain there. Running another analysis with the same folder replaces previous NPSeeker result files but leaves unrelated files untouched.

You can select Auto, Dark, or Light for the interface theme. Auto follows your operating system's light or dark appearance setting.

6.4 Using the Interface on a Remote Server

If NPSeeker runs on a remote server, you can access its interface from your own browser through an SSH tunnel (an encrypted connection that forwards a local port to the server). First, start NPSeeker on the server and specify a port:

./bin/npseeker --gui --no-browser -gui-port 53817

Then open a terminal on your own computer and establish the SSH tunnel:

ssh -L 53817:127.0.0.1:53817 username@server

Keep the SSH connection open. In your local browser, enter the full URL printed by NPSeeker on the server. You can choose a different local port, for example:

ssh -L 9000:127.0.0.1:53817 username@server

In that case, change the URL to use http://127.0.0.1:9000/ while preserving the original ?t= access token.

When working remotely, the interface browses files on the server, not on your local computer. "Pick folder" and "Pick files" also open selection dialogs on the server. These dialogs are unavailable if the server has no graphical desktop; use the interface's built-in file browser instead.

6.5 Configuration File Locations

To make future sessions more convenient, NPSeeker stores recently used folders in recent.txt, the last selected location in lastpick.txt, the interface theme in theme.txt, and the language of the Help page in help-lang.txt. These small files are located in:

Linux~/.config/npseeker/
macOS~/Library/Application Support/npseeker/
Windows%AppData%\npseeker\

Intermediate files created during analysis go into the system temporary folder or the location specified by -tmp-dir, not these configuration folders.

7. Performance and Troubleshooting

7.1 Memory, Running Time, and Temporary Files

  • Memory: -m limits memory used by the main computational steps. Candidate batches loaded under -b and other runtime data require additional memory. If the computer runs low on memory, lower both -m and -b.
  • Threads: -t 0 uses all available hardware threads. Reduce it if you are sharing the computer with other tasks.
  • Time: Running time depends on genome sizes, the number of shared candidates, -mm, available memory, hardware, and disk speed. Increasing k does not necessarily make a run slower. Use -v to see the time spent in each step.
  • Temporary files: NPSeeker creates temporary files during analysis. Their size depends on the data and the memory budget; a smaller memory budget generally requires more temporary disk space. Make sure enough free disk space is available. Temporary files are deleted after normal completion or interruption with Ctrl-C.

7.2 Common Error Messages

Messages about invalid command-line options or parameters begin with "npseeker:". Errors involving input, output, or execution begin with "Error:". The examples below show common problems and what to do about them. If target is replaced by control, the error concerns the control input.

  • Error: target: no FASTA file (*.fasta, *.fna or *.fa) in the folder ...
    The folder contains no files with the recognized FASTA extensions. Use a file list for compressed files (Section 2.2).
  • Error: target: "..." is not found
    The path is incorrect. Note that relative paths start from the folder where you run NPSeeker.
  • Error: target: "..." is not a FASTA file: ...
    The file is not valid FASTA; the text after the colon describes the problem.
  • Error: target: the FASTA file "...", listed in "...", is not found
    A file named in a file list cannot be found.
  • Error: target and control: ...; a genome cannot be both a target and a control
    The same file appears in both input groups.
  • Error: -o: the folder "..." already exists and is not empty; give -w ...
    The output folder is not empty. Choose another folder, or add -w if it is safe to replace previous results.
  • npseeker: option -mm: must be less than the probe length (-k)
    The mismatch cutoff must be smaller than the probe length.
  • npseeker: option -c: no probe of 8 nt has a complexity score above 0.431 ...
    The threshold exceeds the maximum possible score at this probe length (0.431 in this example). Lower it (Section 5.4).
  • Error: -tmp-dir: cannot create the folder "...": ...
    NPSeeker cannot create the temporary folder. Check the path and write permissions.

7.3 Standard Output and Standard Error

Text shown in a terminal comes through two separate streams: standard output (stdout) and standard error (stderr). Both normally appear on the screen. The difference becomes visible when you redirect output to a file, for example by adding > out.txt to a command: stdout goes into that file, while stderr still appears on the screen.

NPSeeker writes results, verbose (-v) logs, and error messages to stdout. Notes beginning with Note:, warnings beginning with Warning:, and progress bars go to stderr. This keeps the redirected result file free of progress messages while allowing you to see warnings on the screen.

7.4 No Probes Found or Slow Execution

If no candidates pass the filters, NPSeeker prints:

Warning: no probe passed the filters; relax the thresholds
         (-max-homopolymer, -c, -e, -min-unfold) to let probes pass.

Try relaxing -min-unfold, -c, -e, or -max-homopolymer (Section 5.4). If the target genomes have very few k-mers in common, try a shorter -k or adjust -min-shared and -mode (Chapter 4). Use -v to see how many candidates remain and how long each processing step takes.

If an analysis is unexpectedly slow, check that the memory needed for -m, candidate batches (-b), and other tasks fits within the available physical memory. Otherwise, the operating system may move memory contents to disk, slowing the computation significantly. If -mm is set high, try its default value for comparison. For large datasets, also check disk speed and free space in the temporary folder.

8. Examples

These examples use macOS and Linux command syntax. On Windows, replace ./bin/npseeker with .\bin\npseeker.exe and / with \ in file paths. Each example can be run independently. If result/ already contains output from an earlier run, choose a new output folder or add -w only if you intend to overwrite the earlier NPSeeker results.

Basic analysis, saving results to result/:

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

Read targets from a file list and cluster them in the listed order:

./bin/npseeker @target.list controls/ -cluster-order input -o result/

Design 31-nucleotide probes with 32 worker threads and 16 GiB of memory:

./bin/npseeker targets/ controls/ -k 31 -t 32 -m 16G -o result/

Give exclusivity and purity greater weight in the overall score:

./bin/npseeker targets/ controls/ -weights exc=2,pur=2 -o result/

Find candidate probes separately for multiple target clusters:

./bin/npseeker targets/ controls/ -min-shared 20000 -mode multi -o result/

Reproduce the bacterial probe rankings in Table 3 of the paper (using the study parameters rather than all defaults; the datasets are a separate download, see Section 0.2):

./bin/npseeker dat/datasets/GP/ dat/datasets/GN/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GP_probes/
./bin/npseeker dat/datasets/GN/ dat/datasets/GP/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GN_probes/

The -min-unfold 70 setting retains the experimentally evaluated Gram-positive probe, whose unfoldability score is 72.54. In the commands above, \ continues a command on the next line in macOS and Linux shells. Use ^ in Windows Command Prompt, a backtick (`) in PowerShell, or enter the entire command on one line.

Part of the dataset used in the paper comes from the ATCC Genome Portal, whose terms of use do not allow redistribution. The dat/datasets/ folder therefore contains corresponding data from NCBI; dat/datasets/sources.txt maps each file to the dataset in the paper. With these data, the sequences and ranks of the two probes in Table 3 are reproduced exactly, but the number of candidates, occurrence counts, and scores differ slightly. One of these genomes, S. enterica ATCC 43976, has only an incomplete assembly at NCBI (part of its 23S rRNA is missing). If it is left out when GN is the target (untick it in the graphical interface, or use the file list @dat/datasets/GN-without-43976.list on the command line), the number of candidates returns to 65, and the top 8 probes in Supplementary Table S3 also match the paper.

Save results as readable tables and output more candidate probes:

./bin/npseeker targets/ controls/ -format txt -top 1000 -o result/
