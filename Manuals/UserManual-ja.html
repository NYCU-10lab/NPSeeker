NPSeeker ユーザーマニュアル

バージョン 1.5.42

NPSeeker について

NPSeeker (Nucleic Acid Probe Seeker) は、ゲノム配列から核酸プローブを設計するプログラムです。主に BioFET (生体電界効果トランジスタ) などのバイオセンサーに用いるプローブの選定を目的としています。核酸プローブは、標的生物の DNA に結合する短い DNA 配列で、生物の検出や識別に利用します。

NPSeeker には、標的 (検出したい生物) と対照 (検出対象から除外したい生物) の 2 組のゲノムを入力します。まず、すべての標的ゲノムに共通する DNA 配列を探します。次に、対照ゲノムとの類似性、標的 DNA との結合の安定性、プローブ自身の折り畳まれやすさを評価し、候補をスコア順に並べます。プローブ長は 5～256 塩基の範囲で指定できます。

関連論文と連絡先:

論文NPSeeker: A BioFET-oriented Nucleic Acid Probe Design Algorithm for Efficient Species Identification and Classification
著者Hao-Yu Peng, Hui Zhi Gan, et al.
Webhttps://10lab.ceb.nycu.edu.tw/NPSeeker/
GitHubhttps://github.com/NYCU-10lab/NPSeeker/
連絡先WadeLo@nycu.edu.tw

NPSeeker を研究に利用した場合は、上記の論文を引用してください。

本マニュアルについて

初めて使う場合は、第 0 章からお読みください。GUI を使いたい場合は、0.1～0.3 節を終えた後、0.4 節に進めます。自分のゲノムデータを用意する方法は第 2 章、設定の変更方法は第 5 章を参照してください。

プログラムにもヘルプ機能があります。-h は主なオプションを、-help はすべてのオプションを表示します。本マニュアルでは、実際の操作手順、使用例、設定の考え方も説明します。プレーンテキスト版 (UserManual-ja.txt) と HTML 版 (UserManual-ja.html) があり、GUI の Help ページからも参照できます。

0. クイックスタート

本マニュアルのコマンドは、特記しない限り macOS と Linux の形式で示します。Windows で操作が異なる場合は、その都度説明します。

コマンドラインでプログラムを実行したことがない場合は、この章の順に操作してください。

0.1 使用環境に合ったファイルをダウンロードする

NPSeeker の Web サイトまたは GitHub から、お使いの OS 用の圧縮ファイルをダウンロードします。Windows、macOS、Linux 用がそれぞれ用意されています。各ファイルには、次の 2 種類の CPU アーキテクチャ向け実行ファイルが含まれています。

x86_64一般的な Intel / AMD 製プロセッサ
arm64Apple M シリーズ搭載 Mac など、ARM 系プロセッサ搭載機

どちらを使えばよいか分からない場合は、次の方法で確認してください。

  • Windows: 「設定 -> システム -> バージョン情報」を開きます。「システムの種類」が x64 なら x86_64、ARM64 なら arm64 です。
  • macOS: 「アップルメニュー -> このMacについて」を開きます。チップが Apple M シリーズなら arm64、Intel プロセッサなら x86_64 です。
  • Linux: ターミナルを開いて uname -m と入力し、Enter キーを押します。x86_64 と表示されたら x86_64、aarch64 なら arm64 です。

0.2 圧縮ファイルの展開

ダウンロードしたファイルを任意のフォルダーに展開します。

  • Windows: 圧縮ファイルを右クリックし、「すべて展開」を選びます。
  • macOS: 圧縮ファイルをダブルクリックします。
  • Linux: ターミナルで tar xzf に続けて圧縮ファイル名を指定します。

展開すると NPSeeker フォルダーができ、次のファイルが含まれます。

bin/x86_64 用実行ファイル npseeker (Windows は npseeker.exe)
bin.arm64/arm64 用実行ファイル
doc/ユーザーマニュアル
dat/sample/初回の解析に使うサンプルデータ

論文で使った細菌のゲノム (グラム陰性菌 GN/ とグラム陽性菌 GP/) は別途ダウンロードします (NPSeeker-1.5.42-datasets.zip または .tar.gz)。展開して、中にある datasets フォルダー (NPSeeker/dat/ の下) をプログラムの dat/ フォルダーに移せば、第 8 章のコマンド例をそのまま使ってテストできます。

インストール作業は不要です。ローカルでの解析にインターネット接続も必要ありません。本マニュアルでは bin/ の x86_64 用ファイルを使います。arm64 の場合は、コマンド中の bin を bin.arm64 に置き換えてください。

0.3 NPSeeker が実行できることを確認する

コマンドラインの画面を開き、NPSeeker フォルダーに移動します。

  • Windows: エクスプローラーで NPSeeker フォルダーを開き、アドレスバーに cmd と入力して Enter を押します。このフォルダーを作業場所とするコマンドプロンプトが開きます。PowerShell でも同じコマンドを使えます。
  • macOS: 「ターミナル」(アプリケーション -> ユーティリティ) を開きます。cd と半角スペースを入力し、NPSeeker フォルダーを画面にドラッグして Enter を押します。
  • Linux: ターミナルを開き、cd で NPSeeker フォルダーに移動します。

次のコマンドを入力し、Enter を押します。

Windows:          .\bin\npseeker.exe -h
macOS, Linux:     ./bin/npseeker -h

NPSeeker のロゴ、使い方、主なオプションが表示されれば準備完了です。

インターネットからダウンロードした署名のないプログラムは、初回実行時に OS のセキュリティ警告が表示される場合があります。

実行を許可する前に、上記の正規の NPSeeker サイトまたは GitHub から入手したファイルであることを確認してください。入手元が不明なプログラムの警告を安易に解除しないでください。

  • Windows: Microsoft Defender SmartScreen により「Windows によって PC が保護されました」と表示され、「実行しない」だけが選べる場合があります。その場合は「詳細情報」を押します。アプリ名と発行元の情報に加えて「実行」ボタンが表示されたら、これを押して起動します。同じ実行ファイルについては、通常、繰り返し確認されません。
  • macOS: Apple による公証を受けていないために起動が拒否される場合があります。ターミナルで xattr -dr com.apple.quarantine に続けて NPSeeker フォルダーのパスを指定してください (フォルダーをドラッグしてパスを入力できます)。または、一度起動を試した後、「システム設定 -> プライバシーとセキュリティ」で npseeker の項目を探し、「このまま開く」を選ぶ方法もあります。
  • Linux: 通常は追加操作は不要です。permission denied と表示されたら、chmod +x bin/npseeker を実行してください。arm64 では chmod +x bin.arm64/npseeker を使い、その後もう一度試してください。

0.4 GUI で最初の解析を行う

コマンドラインを使わずに、ブラウザー上の GUI で操作することもできます。Windows では bin/ にある npseeker.exe をダブルクリックします。macOS と Linux では、ターミナルで次のコマンドを実行します。

./bin/npseeker --gui

ブラウザーに NPSeeker の画面が開きます。まず付属データで試しましょう。Design ページで次の項目を設定します。

  • Target: dat/sample/S.aureus/ を選びます。黄色ブドウ球菌のゲノムが含まれます。
  • Control: dat/sample/yeast/ を選びます。2 種類の酵母のゲノムです。
  • Probe length: 既定値の 25 のままにし、他の設定も変更しません。
  • "Check" を押して入力と設定を確認し、"Go" で解析を開始します。
  • 終了したら Results ページでプローブとスコアを確認し、必要な結果をダウンロードしてください。

GUI は手元のコンピューターで動作し、ゲノムファイルを外部の Web サイトへ送信することはありません。各画面と終了方法については第 6 章をご覧ください。

0.5 コマンドラインで最初の解析を行う

同じ付属データをコマンドラインから解析することもできます。

Windows:          .\bin\npseeker.exe dat\sample\S.aureus\ dat\sample\yeast\
macOS, Linux:     ./bin/npseeker     dat/sample/S.aureus/ dat/sample/yeast/

数秒以内に解析が終わり、プローブがスコア順に表示されます。以下は一部です。

Best probes of cluster 0:
Rank Probe                     Exclus Purity UnFold Affini  Score     Tm
   1 CCGACTAACCCAGAGCGGACGAGCC  50.84  61.32 100.00  64.22  69.10  65.88
   2 GACCCGACTAACCCAGAGCGGACGA  50.84  61.40 100.00  63.68  68.98  64.24
...

1 行が 1 つの候補プローブを表します。Probe は DNA 配列、Score は総合スコアで、高い順に並んでいます。他の列については第 3 章で説明します。最後の Note は、詳しい結果をファイルに保存するには -o が必要であることを知らせています。例えば、次のように指定します。

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

結果は result/ に保存されます (3.2 節)。再実行する場合は別の出力フォルダーを指定するか、以前の結果を置き換えてよい場合に限り -w を追加してください。自分のゲノムを解析するときは、2 つの入力フォルダーを標的用と対照用に置き換えます (第 2 章)。

0.6 プログラムのヘルプを表示する

./bin/npseeker -h               主なオプション
./bin/npseeker -help            すべてのオプション
./bin/npseeker -help -mode      -mode の説明 (-help mode でも可)
./bin/npseeker -help Output     -help の Output セクション
./bin/npseeker -help target     target の説明 (control も指定可)

オプションの指定が正しくない場合、NPSeeker は問題点とヘルプの調べ方を表示し、解析を開始しません。

1. NPSeeker によるプローブの設計と評価

NPSeeker は標的と対照のゲノムを入力として受け取り、候補プローブを順位付きで出力します。標的は検出したい生物、対照は検出対象から除外したい生物です。対照には、標的と混同しやすい近縁種などが該当します。処理は大きく次の 4 段階に分かれます。

  • 共通配列の探索: ゲノムを先頭から走査し、連続する k 塩基を順に取り出します。この短い配列を k-mer と呼びます。例えば ACGTA の 3-mer は ACG、CGT、GTA です。すべての標的ゲノムに存在する k-mer が候補となります。1 本のプローブで全標的を検出するには、共通配列が必要です。DNA は相補的な 2 本鎖なので、k-mer とその逆相補配列を同じ k-mer として扱います。
  • 候補のフィルタリング: 塩基組成が偏った配列、同じ塩基が長く続く配列 (例: AAAA)、自身が折り畳まれたり、同じプローブ同士が結合したりしやすい配列を除外します。こうして後の重い計算を減らします。
  • 対照ゲノムの検査: 残った候補について、対照中の完全一致配列、数塩基だけ異なる類似配列、プローブの短い部分配列の出現を調べます。
  • スコア付けと順位付け: 次の 4 項目を計算して総合スコアを求めます。
Exclusivity標的に存在し、対照にはほとんど存在しない程度
Purity対照中の類似配列や短い一致部分が少なく、意図しない結合を起こしにくい程度
Unfoldability自身が折り畳まれにくく、標的と結合できる状態を保ちやすい程度
Affinity標的 DNA への結合の強さを、結合の自由エネルギーから予測

各項目と総合スコアは 0～100 の範囲で、高いほど望ましい性質を示します。既定では 4 項目を同じ重みで平均します。これらは実験で検証する候補の優先順位を付けるための計算値であり、BioFET の信号強度の実測値でも、実験性能を保証する値でもありません。

標的ゲノム間の差が大きく、全体で共有する k-mer が少ない場合は、標的を複数のクラスターに分け、各クラスターから候補を探します。クラスタリングと出力モードは第 4 章、スコアの式とアルゴリズムの詳細は研究論文を参照してください。

2. 標的ゲノムと対照ゲノムの準備

コマンドラインでは、最初の 2 つの引数に標的と対照をこの順で指定し、その後にオプションを続けます。

./bin/npseeker <target> <control> [options]

1 ゲノムにつき 1 つの FASTA ファイルを用意してください。FASTA は DNA 配列を記録するテキスト形式で、一般に拡張子 .fasta、.fna、.fa が使われます。標的と対照はそれぞれ、フォルダー、ファイルリスト、単一ファイルのいずれかで指定できます。

2.1 フォルダーを指定する

フォルダーを指定すると、その直下の .fasta、.fna、.fa で終わるファイルを読み取り、1 ファイルを 1 ゲノムとして扱います。拡張子はすべて小文字でもすべて大文字でも構いません (例: .FASTA)。サブフォルダーは検索しません。

./bin/npseeker targets/ controls/

フォルダー内の圧縮ファイル (.gz、.zst) は読み取り対象外です。圧縮 FASTA ファイルを使う場合は、ファイルリストで指定してください。

2.2 ファイルリストを指定する

ファイルリストは、各行に FASTA ファイルのパスを 1 つずつ記したテキストファイルです。リストとして読み取らせるには、名前の先頭に @ を付けます。

./bin/npseeker @target.list @control.list

例えば target.list は次のようになります。

# Three target genomes
genomes/strain_A.fasta
genomes/strain_B.fna.gz
/data/others/strain_C.fa
  • 空行と # で始まる行は無視されます。# はコメントにも使えます。
  • 相対パスは、リストファイルの保存場所ではなく、NPSeeker を実行する作業ディレクトリからの相対パスとして解釈されます。
  • 別々のフォルダーにあるファイルや、gzip (.gz)、zstd (.zst) で圧縮した FASTA ファイルも指定できます。
  • -cluster-order input を指定すると、リスト中の順番がクラスタリング時の処理順になります (第 4 章)。

@ を付けずに指定したファイルでも、FASTA 形式でなければファイルリストとして解釈されます。意図を明確にするため、@ の使用を推奨します。

2.3 単一の FASTA ファイルを指定する

標的または対照に 1 ゲノムしかない場合は、その FASTA ファイルを直接指定できます。圧縮 FASTA ファイルにも対応しています。

./bin/npseeker strain_A.fasta controls/

2.4 FASTA の内容と入力チェック

  • 1 つの FASTA ファイルには、染色体やプラスミドなどの複数の配列レコードが含まれていても構いません。全レコードを 1 ゲノムとみなします。
  • A、C、G、T は大文字と小文字のどちらも受け付けます。それ以外の文字 (例: N) では配列を区切り、その位置をまたぐ k-mer は数えません。
  • NPSeeker は入力ファイルの FASTA 形式を検査します。ファイルが見つからない場合や形式が不正な場合は、エラーを表示して停止します (7.2 節)。
  • 同じファイルを標的と対照の両方に指定することはできません。重複が見つかった場合は、そのファイルを示して停止します。

標的と対照の選び方は、プローブの順位に直接影響します。対照には、無関係な生物を適当に選ぶのではなく、実際の検査で標的と混同する可能性がある生物を含めることを推奨します。

3. 結果の見方とプローブの選び方

3.1 画面に表示される結果

-o を指定しない場合、上位 -top 件 (既定値は 200) のプローブが画面に表示されます。表示項目は Rank、Probe、4 つのスコア、Score、Tm です。-o を指定した場合は詳細をファイルに保存し、画面には保存したファイルの一覧を表示します。-v を追加すると設定値や処理時間も確認できます。

3.2 出力ファイル

例えば -o result/ を指定すると、既定では CSV 形式 (カンマ区切り) で次のファイルが保存されます。

cluster_N_probes.csvプローブ候補の順位表。N は 0 から始まるクラスター番号
cluster.csv各ゲノムが属するクラスター
flag.csv今回の解析に使用した設定値

-format txt を指定すると、空白で列をそろえた読みやすいテキスト表になります。CSV は Excel などの表計算ソフトや他のプログラムでの処理に便利です。single と multi では出力ファイル数が異なります (第 4 章)。

cluster_N_probes.csv の各項目は次のとおりです。

Rankプローブの順位
Probeプローブ配列 (5' 端から 3' 端への向きで記載)
Tgt標的ゲノム中の出現回数
Ctl対照ゲノム中の完全一致の出現回数。少ないほど望ましい
ExclusTgt と Ctl から計算する Exclusivity スコア
MMs対照中の類似配列に関する値。小さいほど望ましい
Subseq対照中の短いプローブ断片に関する値。小さいほど望ましい
PurityMMs と Subseq から計算する Purity スコア
SelfAnプローブ自身が折り畳まれやすい程度 (自己アニーリング) 小さいほど望ましい
Dimer同じプローブ同士が結合しやすい程度 (二量体形成) 小さいほど望ましい
UnFoldSelfAn と Dimer から計算する Unfoldability スコア
Affini結合の自由エネルギーに基づく Affinity スコア
Score4 項目のスコアの加重平均
Tm融解温度 (°C)。プローブと標的からなる二本鎖の半数が解離する温度で、Score には含めない

Exclus、Purity、UnFold、Affini、Score は 0～100 の範囲で、値が高いほど望ましいことを示します。標的が複数のクラスターに分かれる場合、Tgt には自分のクラスター以外の標的ゲノム中にある類似配列も含まれます。したがって、必ずしも完全一致の出現回数だけを表すわけではありません。

cluster.csv には Group (target または control)、Cluster (標的のクラスター番号。対照は空欄)、File (ファイル名) が記録されます。flag.csv には Option と Value が記録され、解析時の設定を確認できます。

指定した出力フォルダーがなければ自動作成されます。既に存在していても、空なら使用できます。中にファイルがある場合は、既存データを保護するためエラーで停止します。以前の結果を置き換えてよい場合に限り -w を指定してください。過去の NPSeeker 出力 (cluster_N_probes、cluster、flag) は削除されますが、無関係なファイルは残ります。

3.3 プローブを選ぶ際のポイント

Score は候補選定の出発点になりますが、総合スコアだけで判断しないでください。用途に応じて、次の項目も確認します。

  • Ctl: 0 より大きければ、対照ゲノムにも完全一致する配列があります。非標的生物への結合 (交差反応) の可能性に注意してください。
  • Tgt: 出現回数が多いほど信号が強くなる可能性はありますが、反復配列に由来する場合もあります。信号強度を直接予測する数値ではありません。
  • Purity と UnFold: 非標的配列への意図しない結合や、プローブが自身で折り畳まれるリスクを比較するための指標です。
  • Tm: 測定温度に制約がある場合や複数のプローブを同時に使う場合は、融解温度を比較してください。同じ実験に使うプローブは Tm が近い方が望ましいでしょう。

必要に応じて NCBI BLAST で他の生物に類似配列がないか調べたり、UNAFold (mfold) で折り畳み構造を予測したりできます。Results ページには両サービスへのリンクがありますが、選択したプローブ配列が外部サイトへ送信されます (6.2 節)。特定の BioFET で実際に利用できるかどうかは、最終的に目的の実験条件で確かめる必要があります。

4. 標的ゲノムのクラスタリングと single / multi モード

すべての標的ゲノムに共通する k-mer が少なすぎる場合、NPSeeker は標的を複数のクラスターに分けます。ゲノムを 1 つずつ処理し、新しいゲノムを加えてもクラスター全体の共通 k-mer が -min-shared 個以上残るときだけ、そのクラスターに加えます。条件を満たさなければ別のクラスターへ回します。このクラスターは候補探索のための計算上の区分で、進化的・系統学的な分類を意味するものではありません。

-cluster-order は、標的ゲノムを処理する順序を指定します。

  • auto (既定値): ゲノム間の共通 k-mer 数に基づき、決定的な順序を選びます。同じゲノム集合なら、入力ファイルの並びを変えてもクラスタリング結果は変わりません。
  • input: ファイルリストなど、使用者が指定した順序に従います。特定の参照ゲノムを最初のクラスターの起点にしたい場合に使います。

-min-shared の既定値は 1 です。新しいゲノムを加えた後も、クラスター全体に共通する k-mer が 1 個以上あれば同じクラスターに入るため、通常は 1 つのクラスターになります。値を増やすとクラスター数が増える場合があり、各クラスターで得られる候補も変わります。

標的が複数のクラスターに分かれたときは、-mode で出力方法を選びます。

  • single (既定値): 全クラスターの候補をまとめて順位付けし、総合順位の上位 -top 件だけを cluster_0_probes.csv に保存します。上位候補の多くが同じクラスターに由来する場合もあります。
  • multi: クラスターごとに順位付けし、それぞれ上位 -top 件までを cluster_0_probes.csv、cluster_1_probes.csv などに保存します。各標的クラスターの候補を得たい場合に使用します。

multi モードで各クラスターからプローブを選ぶと、計算上は全標的クラスターを対象とするプローブの組を構成できます。ただし、実際の検出性能には実験による検証が必要です。ゲノムの所属先は cluster.csv で確認できます。あるクラスターの候補がすべてフィルターで除外された場合は警告が表示され、他のクラスターの結果はそのまま保存されます。

5. オプションとパラメータ

オプションは標的と対照の入力の後に指定します。値を取るオプションは、-k 31 のように半角スペースで区切って記します。-v、-w、--gui のようなスイッチには値を付けません。-k と -kmer のように短い名前と長い名前がある場合は、どちらでも指定できます。数値には指数表記も使えます。例えば 1e7 は 10,000,000 です。以下の分類は -help の出力に従います。各節の見出しにある括弧内は -help のセクション名です。付録 A にオプション一覧をまとめています。

5.1 プローブ長と計算資源 (General settings)

-k, -kmer [整数、5～256、既定値 25]

プローブの長さを塩基数で指定します。目的の測定法に合った長さを選んでください。k が大きいほど、互いに異なる標的ゲノムの間で同一の長い配列が共有されにくくなり、クラスター数が増える場合があります。実行時間は主にゲノムサイズと候補数に左右されるため、プローブが長いほど遅くなるとは限りません (論文 Figure 4)。

-t, -threads [整数、既定値 0]

並列処理に使うスレッド数を指定します。0 は利用可能なハードウェアスレッドをすべて使います。他の作業とコンピューターを共用する場合は、値を小さくするとよいでしょう。

-m, -memory [容量、既定値は物理メモリの半分、上限 8G]

主な計算処理で使うメモリの予算を指定します。例えば -m 8G や -m 512M とします。単位なしの数値は GiB として解釈されます。予算を減らすと分割処理が増えて遅くなることがありますが、結果は変わりません。候補を読み込むバッチ (-b) とその他の実行時データに必要なメモリは、この予算に含まれません (5.5 節)。

5.2 出力と実行ログ (Output)

-o, -out-dir [フォルダー、既定ではファイル保存なし]

結果ファイルの保存先を指定します (3.2 節)。-o を省略すると、画面には項目数の少ない結果表だけが表示されます。結果を保存し、後で分析、比較、再現したい場合は出力フォルダーを指定してください。

-w, --overwrite

-o で指定したフォルダーが空でなくても使用できるようにします。以前の NPSeeker 結果ファイルを削除してから新しい結果を書き込み、その他のファイルは残します (3.2 節)。

-top [整数、既定値 200]

各順位表で何件の上位プローブを出力するか指定します。より多くの候補を確認したいときに増やしてください。ただし、大きすぎる値は出力ファイル、メモリ使用量、実行時間を増やす場合があります。

-format [csv または txt、既定値 csv]

結果ファイルの形式を指定します。csv はカンマ区切りで、表計算ソフトや他のプログラムでの処理に適しています。txt は空白で桁をそろえた表で、直接読むのに便利です。

-v, --verbose

入力情報、設定、処理段階、各段階の実行時間などを詳しく表示します。問題の調査や、大規模な解析の進行確認に役立ちます。GUI から開始した解析では常に詳細ログが記録されます。

5.3 クラスタリングと順位付け (Target clustering, Probe ranking)

-cluster-order [auto または input、既定値 auto]

標的ゲノムをクラスタリングする際の処理順を指定します。auto では入力順に依存せず、input では指定された順番を使います。詳しくは第 4 章を参照してください。

-min-shared [整数、既定値 1]

クラスター内の全ゲノムで共有しなければならない k-mer の最小数です。値を大きくするとクラスターが増える傾向がありますが、すべてのクラスターで適切なプローブが見つかるとは限りません (第 4 章)。

-mode [single または multi、既定値 single]

標的が複数のクラスターに分かれた場合にのみ違いが生じます。single は全クラスターの候補をまとめて順位付けし、multi はクラスターごとに順位表を作ります。選び方は第 4 章をご覧ください。

-weights [KEY=WEIGHT をカンマ区切り、既定値は各項目とも 1]

Exclusivity (exc)、Purity (pur)、Unfoldability (unf)、Affinity (aff) の総合スコアへの重みを調整します。例えば、次のように指定します。

-weights exc=2,pur=2

この場合、Exclusivity と Purity の重みが 2 倍になり、指定していない unf と aff は 1 のままです。総合スコアは次の式で求めます。

Score = (w_exc*Exclus + w_pur*Purity + w_unf*UnFold + w_aff*Affini)
        / (w_exc + w_pur + w_unf + w_aff)

重みは 0 以上で、すべて 0 にはできません。重みが 0 の項目も計算されますが、総合スコアには寄与しません。重みを増やしても、ある項目のスコアが低い候補が直接除外されるわけではなく、順位への影響が変わります。

-mm, -mismatch-cutoff [整数、既定値は floor(プローブ長 / 10)]

Purity の評価時に、対照中の配列をプローブと類似とみなす塩基の不一致数の上限を指定します。値を大きくすると多くの類似配列が検出されますが、時間とメモリの使用量が大幅に増える場合があります。値はプローブ長より小さくする必要があります。

5.4 候補のフィルタリング (Candidate filtering)

NPSeeker は計算負荷の高い対照ゲノムとの比較前に候補を絞り込みます。条件が厳しすぎると候補が残らない場合があります。そのときは、次のしきい値を緩めてみてください。

-max-homopolymer [整数、既定値 3]

ホモポリマー (homopolymer) とは、AAAA のように同じ塩基が連続する配列です。このオプションで許容する最長の連続数を指定します。既定値の 3 なら AAA は許容され、AAAA 以上の連続がある候補は除外されます。値を増やすと、長い連続塩基を含む候補も残りやすくなります。

-c, -min-complexity [数値、0～1、既定値 0.5]

配列複雑度の下限を指定します。4 種類の塩基の割合が均等なほど高い値になります。しきい値を超える候補だけが残ります。

-e, -min-entropy [数値、0～2、既定値 1.5]

配列エントロピーの下限を指定します。エントロピーは配列パターンの多様さを表し、ACACAC のような反復配列では低くなります。しきい値を超える候補だけが残ります。短いプローブでは、複雑度とエントロピーの理論上の最大値も低くなります。指定値がその長さでの最大値を超えると、NPSeeker はエラーとともに最大値を表示します。

-prefilter [T または F、既定値 T]

対照ゲノムの走査前に Unfoldability によるフィルタリングを行うか指定します。T は -min-unfold 未満の候補を除外し、後の比較処理を減らします。F はこの事前フィルターを無効にしますが、各候補の Unfoldability スコアは通常どおり計算されます。

-min-unfold [数値、0～100、既定値 75]

事前フィルターに使う Unfoldability のしきい値です。下げると、自身が折り畳まれやすい候補も残り、後の比較処理が増える場合があります。あるバッチの全候補がしきい値に届かないときは、そのバッチの事前フィルターを省略します。論文で評価したグラム陽性菌用プローブの Unfoldability は 72.54 です。その順位を再現するには -min-unfold 70 を指定します (第 8 章)。

5.5 詳細オプション (Advanced)

通常は既定値を変更する必要はありません。

-b, -batch-size [整数、既定値 1e7]

1 回に読み込んでフィルタリングする候補 k-mer の数を指定します。k = 25 では 1 候補あたり約 170 バイトなので、既定の 1,000 万候補には約 1.58 GiB のメモリが必要です。この容量は -m の予算とは別です。メモリの少ないコンピューターでは値を減らしてください。ただし、バッチ数が増えて実行時間が長くなる場合があります。

-s, -min-subseq [整数、既定値 7]

Purity の評価に使う短いプローブ断片の最小長を指定します。-subseq-step と組み合わせて使用します。

-subseq-step [整数、既定値は ceiling(プローブ長 / 10)]

Purity の評価で調べる断片長を、何塩基ずつ短くするか指定します。例えば k = 25 では既定の間隔は 3 で、長さ 22、19、16、13、10、7 の断片を調べます。間隔を小さくすると調べる長さが増え、処理負荷も大きくなります。

-tmp-dir [フォルダー、既定値はシステムの一時フォルダー]

計算に必要な一時ファイルの保存先を指定します。NPSeeker はその下に専用フォルダーを作り、正常終了時や Ctrl-C による中断時に削除します。システムディスクの空き容量が足りない場合は、別のディスクを指定します。

5.6 GUI とヘルプ (Graphical interface)

--guiローカル GUI を起動し、直接の解析は行わない
-gui-port [整数]GUI が使用するポート番号 (URL のコロンの後の数値) 既定値は自動選択
--no-browserブラウザーを開かず、GUI の URL だけを表示
--tab既定のブラウザーのタブで GUI を開く
-h簡易ヘルプを表示
-help [KEYWORD]全ヘルプまたは指定項目・セクションの説明を表示

--gui と併用できるのは -gui-port、--no-browser、--tab だけです。-k など解析に関する設定は GUI 内で指定してください。--gui とともにコマンドラインで指定するとエラーになります。詳しくは第 6 章をご覧ください。

6. グラフィカルインターフェース

NPSeeker は手元のコンピューターで小さな Web サーバーを起動し、ブラウザーから操作できるようにします。接続先は 127.0.0.1 で、同じコンピューターからのみアクセスできます。解析そのものは NPSeeker が行い、ゲノムファイルが外部の Web サイトにアップロードされることはありません。同じ設定なら GUI とコマンドラインの解析結果は一致します。

6.1 起動と接続

  • Windows: bin/ 内の npseeker.exe をダブルクリックするか、コマンドプロンプトで .\bin\npseeker.exe --gui を実行します。プログラムのメッセージが表示されるコンソール画面 (黒い文字画面) が開くので、GUI の使用中は閉じないでください。
  • macOS、Linux: ターミナルで ./bin/npseeker --gui を実行します。

通常はブラウザーが自動的に開き、次のような URL も表示されます。

http://127.0.0.1:53817/?t=1a2b3c...

?t= 以降は、そのセッション用のアクセストークンです。ブラウザーが自動的に開かない場合は、表示された URL 全体をコピーして開いてください。トークンを含む URL をむやみに第三者に知らせないでください。

既定では独立したウィンドウで GUI が開きます。Edge や Chrome などではアドレスバーのないアプリケーション形式のウィンドウ、Firefox では新しいウィンドウになります。--tab を付けると、既定のブラウザーのタブで開けます。

6.2 各ページの機能

DesignTarget、Control、出力フォルダー (省略可)、プローブ長を設定。フォルダー単位、または個別の FASTA ファイルを選べます。圧縮ファイルや別の場所のファイルも指定できます。"Tick all" はフォルダー内のファイルをまとめて選択します。"Pick folder" と "Pick files" は OS の選択画面を開きます。詳細設定は必要に応じて展開します。空欄は既定値を使用します。"Check" は入力と設定を検査し、"Go" は解析を開始します。
Run現在の処理段階、進行状況、実行ログを表示します。"Cancel" で解析を中止できます。
Resultsプローブの順位、配列、各スコアを確認できます。列の見出しを押すと並び替えられますが、Rank の値は NPSeeker による元の順位のままです。プローブを選ぶと逆相補配列や融解温度を確認し、配列をコピーできます。結果ファイルは個別、または zip 形式で一括ダウンロード可能。
Helpマニュアルを読み、表示言語を切り替えます。
Aboutプログラム、論文、著者、連絡先の情報を表示します。

Results ページには、次の外部サービスへのリンクもあります。

  • BLAST at NCBI: 選択した配列で NCBI BLAST を開き、他の生物に類似配列があるか調べます。
  • Fold at UNAFold: 配列を UNAFold (mfold) に送り、DNA の折り畳みを予測します。Web サイトのフォームの既定条件 (37 °C、1 M Na+) を使います。

この 2 つのサービスにはインターネット接続が必要で、選択した配列が外部サイトへ送信されます。未公開配列を扱う場合は、外部サービスへ送ってよいか事前に確認してください。

出力フォルダーを指定しない場合、GUI は結果をローカルディスクに一時保存します。GUI を終了すると一時保存した結果は削除されます。必要な結果は終了前にダウンロードしてください。

6.3 Close、Exit と結果の保存

  • "Close" はブラウザーのページだけを閉じます。NPSeeker は動き続けます。再び開くには、コンソールに表示された URL にアクセスしてください。
  • "Exit" は GUI を終了し、実行中の解析も停止します。コンソール画面を閉じるか、Ctrl-C を押した場合もプログラムは終了します。
  • GUI のページをすべて閉じたまま 5 分を超え、解析も実行していない場合、NPSeeker は自動終了します。未ダウンロードの一時保存結果も削除されます。

"Exit" または "Close" を押すと確認画面が表示されます。解析の実行中や、まだダウンロードしていない一時保存結果がある場合は、その旨が示されます。

出力フォルダーを指定していれば結果はその場所に残ります。同じフォルダーで再び解析すると、以前の NPSeeker 結果ファイルは置き換えられ、関係のないファイルはそのまま残ります。

GUI の配色は Auto、Dark、Light から選べます。Auto は OS のライト / ダークモードに合わせます。

6.4 リモートサーバー上の GUI を使う

NPSeeker をリモートサーバーで動かす場合、SSH トンネル (手元のポートをサーバー側のポートへ転送する暗号化接続) を使えば、自分のブラウザーから GUI を操作できます。まずサーバー上でポートを指定して起動します。

./bin/npseeker --gui --no-browser -gui-port 53817

次に、自分のコンピューターでターミナルを開き、SSH トンネルを作ります。

ssh -L 53817:127.0.0.1:53817 username@server

SSH 接続を維持したまま、自分のブラウザーでサーバーが表示した URL 全体を開いてください。手元のポート番号だけを変えることもできます。例えば:

ssh -L 9000:127.0.0.1:53817 username@server

この場合、URL の接続先を http://127.0.0.1:9000/ に変更し、元の ?t= 以降のアクセストークンはそのまま残します。

リモート利用時、GUI に表示されるのはサーバー上のファイルです。"Pick folder" と "Pick files" が開く選択画面もサーバー側のものです。サーバーにデスクトップ環境がない場合は、この選択画面を使えません。その場合は GUI 内蔵のファイルブラウザーを使用してください。

6.5 設定ファイルの場所

NPSeeker は、最近使ったフォルダーを recent.txt、最後に選んだ場所を lastpick.txt に記録し、次回の操作に利用します。保存先は次のとおりです。

Linux~/.config/npseeker/
macOS~/Library/Application Support/npseeker/
Windows%AppData%\npseeker\

解析中の一時ファイルはここではなく、システムの一時フォルダー、または -tmp-dir で指定した場所に保存されます。

7. 性能とトラブルシューティング

7.1 メモリ、実行時間、一時ファイル

  • メモリ: -m は主要な計算処理のメモリ予算です。-b で読み込む候補やその他の実行時データには別途メモリが必要です。不足する場合は -m と -b の両方を減らしてください。
  • スレッド: -t 0 は利用できるハードウェアスレッドをすべて使います。他の処理とコンピューターを共用する場合は減らしてください。
  • 時間: ゲノムサイズ、共通候補の数、-mm、メモリ、ハードウェア、ディスク速度に左右されます。k を大きくしても、必ずしも遅くなりません。-v で各段階の実行時間を確認できます。
  • 一時ファイル: 解析中に一時ファイルが作られます。必要な容量はデータとメモリ予算によって変わり、予算が小さいほど一時ファイルが多くなる傾向があります。十分な空き容量を確保してください。正常終了時や Ctrl-C による中断時に一時ファイルは削除されます。

7.2 よくあるエラーメッセージ

コマンドラインのオプションやパラメータが不正な場合、メッセージは "npseeker:" で始まります。入出力や実行中のエラーは "Error:" で始まります。よくある例と対処方法を以下に示します。target の代わりに control と表示される場合は、対照側の入力に問題があります。

  • Error: target: no FASTA file (*.fasta, *.fna or *.fa) in the folder ...
    フォルダーに該当する拡張子の FASTA ファイルがありません。圧縮したファイルはファイルリストで指定してください (2.2 節)。
  • Error: target: "..." is not found
    指定したパスが間違っています。相対パスは NPSeeker を実行したフォルダーを基準に解釈される点にも注意してください。
  • Error: target: "..." is not a FASTA file: ...
    FASTA 形式として不正です。コロン以降に理由が表示されます。
  • Error: target: the FASTA file "...", listed in "...", is not found
    ファイルリストに記載したファイルが見つかりません。
  • Error: target and control: ...; a genome cannot be both a target and a control
    同じファイルが標的と対照の両方に含まれています。
  • Error: -o: the folder "..." already exists and is not empty; give -w ...
    出力フォルダーが空ではありません。別の場所を選ぶか、以前の結果を置き換えてよい場合に限り -w を指定してください。
  • npseeker: option -mm: must be less than the probe length (-k)
    -mm はプローブ長より小さくする必要があります。
  • npseeker: option -c: no probe of 8 nt has a complexity score above 0.431 ...
    設定したしきい値が、このプローブ長で取り得る最大値を超えています。この例では最大値は 0.431 です。値を下げてください (5.4 節)。
  • Error: -tmp-dir: cannot create the folder "...": ...
    一時フォルダーを作成できません。パスと書き込み権限を確認してください。

7.3 標準出力と標準エラー出力

ターミナルに表示される文字には、標準出力 (stdout) と標準エラー出力 (stderr) という 2 つの経路があります。通常はどちらも同じ画面に表示されます。コマンドの末尾に > out.txt を付けるなど、出力をファイルへリダイレクトすると違いが分かります。stdout はファイルに入り、stderr はそのまま画面に表示されます。

NPSeeker は結果、-v の実行ログ、エラーメッセージを stdout に出力します。Note: で始まる通知、Warning: で始まる警告、進行状況バーは stderr に出力します。そのため、結果をファイルに保存しても進行状況が混ざらず、警告は画面上で確認できます。

7.4 プローブが見つからない場合や解析が遅い場合

フィルターを通過する候補が 1 つもない場合、次の警告が表示されます。

Warning: no probe passed the filters; relax the thresholds
         (-max-homopolymer, -c, -e, -min-unfold) to let probes pass.

-min-unfold、-c、-e、-max-homopolymer の条件を緩めてみてください (5.4 節)。標的同士で共有する k-mer が非常に少ない場合は、-k を短くするか、-min-shared と -mode を調整します (第 4 章)。-v を付けると、各処理段階で残った候補数と実行時間を確認できます。

解析が予想以上に遅い場合は、-m の予算、-b のバッチ、その他の処理に必要なメモリの合計が、使用できる物理メモリ内に収まるか確認します。不足すると OS がメモリ内容をディスクへ退避し、処理が大きく遅くなることがあります。-mm を大きくしている場合は既定値に戻して比較します。大きなデータでは、ディスク速度や一時フォルダーの空き容量も確認してください。

8. 使用例

以下は macOS と Linux のコマンド形式です。Windows では ./bin/npseeker を .\bin\npseeker.exe に、ファイルパス中の / を \ に置き換えてください。各例は独立して実行できます。result/ に以前の結果が残っている場合は、別の出力フォルダーを指定するか、以前の結果を置き換えてよい場合に限り -w を追加してください。

基本的な解析。結果を result/ に保存します。

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

ファイルリストから標的を指定し、その並び順でクラスタリングします。

./bin/npseeker @target.list controls/ -cluster-order input -o result/

長さ 31 塩基のプローブを、32 スレッド、16 GiB のメモリ予算で設計します。

./bin/npseeker targets/ controls/ -k 31 -t 32 -m 16G -o result/

Exclusivity と Purity の総合スコアに対する重みを大きくします。

./bin/npseeker targets/ controls/ -weights exc=2,pur=2 -o result/

複数の標的クラスターについて、候補をそれぞれ探索します。

./bin/npseeker targets/ controls/ -min-shared 20000 -mode multi -o result/

論文 Table 3 の細菌プローブの順位を再現します。すべて既定値を使うのではなく、研究時の設定を指定します。データセットは別途ダウンロードします (置き方は 0.2 節を参照)。

./bin/npseeker dat/datasets/GP/ dat/datasets/GN/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GP_probes/
./bin/npseeker dat/datasets/GN/ dat/datasets/GP/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GN_probes/

-min-unfold 70 は、実験で使ったグラム陽性菌用プローブ (Unfoldability スコア 72.54) を残すための設定です。上記の \ は、macOS / Linux でコマンドを次の行に続ける記号です。Windows のコマンドプロンプトでは ^、PowerShell ではバッククォート (`) を使います。コマンド全体を 1 行で入力することもできます。

論文のデータセットの一部は ATCC のゲノムデータベース (ATCC Genome Portal) から取得したもので、ATCC の利用規約では再配布が認められていません。そのため dat/datasets/ には NCBI の対応するデータを収録しています。両者のファイルごとの対応は dat/datasets/sources.txt を参照してください。このデータでも、Table 3 の 2 本のプローブの配列と順位は論文と同じですが、候補の総数、出現回数、各スコアはわずかに異なります。このうち S. enterica ATCC 43976 は、NCBI には不完全なアセンブリしかありません (23S rRNA の一部が欠けています)。GN を標的とする計算でこのゲノムを外すと (グラフィカルインターフェースではチェックを外し、コマンドラインではファイルリスト @dat/datasets/GN-without-43976.list を使います)、候補数は 65 に戻り、補足資料 Table S3 の上位 8 本も論文と一致します。

読みやすいテキスト表で保存し、出力するプローブ数を増やします。

./bin/npseeker targets/ controls/ -format txt -top 1000 -o result/
