Manuel d'utilisation de NPSeeker

Version 1.5.42

Présentation de NPSeeker

NPSeeker (Nucleic Acid Probe Seeker) est un logiciel de conception de sondes nucléiques à partir de séquences génomiques. Il est principalement destiné à sélectionner des sondes pour des biocapteurs tels que les BioFET (transistors à effet de champ utilisés en biodétection). Une sonde nucléique est un court fragment d'ADN capable de s'hybrider à l'ADN d'un organisme que l'on souhaite détecter ou identifier.

NPSeeker utilise deux ensembles de génomes : les cibles (organismes à détecter) et les témoins négatifs, appelés contrôles dans ce manuel (organismes auxquels les sondes ne devraient pas se lier). Le logiciel recherche d'abord les séquences d'ADN communes à toutes les cibles. Il évalue ensuite leur similarité avec les génomes contrôles, leur capacité à s'hybrider aux séquences cibles et leur propension à se replier sur elles-mêmes. Les sondes candidates sont enfin classées selon leurs scores. Leur longueur peut être fixée entre 5 et 256 nucléotides.

0. Prise en main

Sauf indication contraire, les commandes de ce manuel sont écrites pour macOS et Linux. Les différences propres à Windows sont précisées au besoin.

Si vous n'avez jamais utilisé un programme en ligne de commande, suivez les étapes de ce chapitre dans l'ordre.

0.1 Télécharger la version adaptée

Téléchargez depuis le site de NPSeeker ou GitHub l'archive correspondant à votre système : Windows, macOS ou Linux. Chaque archive contient des exécutables pour deux architectures de processeur :

x86_64La plupart des processeurs Intel et AMD
arm64Mac équipés d'une puce Apple de série M et autres ordinateurs ARM

Si vous ne connaissez pas l'architecture de votre ordinateur :

  • Windows : ouvrez « Paramètres -> Système -> Informations système ». Dans « Type du système », la valeur x64 correspond à x86_64 et la valeur ARM64 à arm64.
  • macOS : ouvrez « Menu Pomme -> À propos de ce Mac ». Les Mac à puce Apple de série M utilisent arm64 ; les Mac à processeur Intel utilisent x86_64.
  • Linux : ouvrez un terminal, saisissez uname -m puis appuyez sur Entrée. La commande affiche x86_64 ou aarch64 (qui correspond à arm64).

0.2 Décompresser l'archive

Décompressez l'archive téléchargée dans le dossier de votre choix :

  • Windows : faites un clic droit sur l'archive et choisissez « Extraire tout ».
  • macOS : double-cliquez sur l'archive.
  • Linux : dans un terminal, exécutez tar xzf suivi du nom de l'archive.

Le dossier NPSeeker obtenu contient :

bin/Exécutable x86_64 : npseeker (npseeker.exe sous Windows)
bin.arm64/Exécutable arm64
doc/Manuels d'utilisation
dat/sample/Données d'exemple pour une première analyse

Les génomes bactériens utilisés dans l'article NPSeeker (Gram négatif GN et Gram positif GP) sont à télécharger séparément (NPSeeker-1.5.42-datasets.zip ou .tar.gz). Vous pouvez l'extraire, puis déplacer le dossier datasets qu'il contient (sous NPSeeker/dat/) dans le dossier dat du programme, afin d'exécuter tels quels les exemples de commandes du chapitre 8.

NPSeeker ne nécessite aucune installation ni connexion Internet pour effectuer une analyse locale. Les commandes de ce manuel utilisent l'exécutable x86_64 placé dans bin/. Sur un ordinateur arm64, remplacez bin par bin.arm64 dans les commandes.

0.3 Vérifier le lancement du programme

Ouvrez une fenêtre de ligne de commande et placez-vous dans le dossier NPSeeker décompressé :

  • Windows : ouvrez le dossier NPSeeker dans l'Explorateur de fichiers. Saisissez cmd dans la barre d'adresse, puis appuyez sur Entrée. Une fenêtre d'invite de commandes s'ouvre directement dans ce dossier. Vous pouvez aussi utiliser PowerShell avec les mêmes commandes.
  • macOS : ouvrez « Terminal » (Applications -> Utilitaires). Saisissez cd suivi d'une espace, faites glisser le dossier NPSeeker dans la fenêtre du terminal, puis appuyez sur Entrée.
  • Linux : ouvrez un terminal et utilisez cd pour rejoindre le dossier NPSeeker.

Saisissez ensuite la commande adaptée à votre système et appuyez sur Entrée :

Windows:          .\bin\npseeker.exe -h
macOS, Linux:     ./bin/npseeker -h

Si le logo de NPSeeker, sa syntaxe d'utilisation et ses principales options s'affichent, le programme est prêt à fonctionner.

Lors du premier lancement, le système peut afficher un avertissement de sécurité, car l'exécutable téléchargé ne possède pas de signature numérique.

Avant d'autoriser son exécution, vérifiez que NPSeeker provient du site officiel ou du dépôt GitHub indiqués dans « Présentation de NPSeeker ». N'ignorez jamais un avertissement pour un logiciel d'origine inconnue.

  • Windows : une fenêtre bleue « Windows a protégé votre ordinateur » peut apparaître. Microsoft Defender SmartScreen y affiche d'abord seulement le bouton « Ne pas exécuter ». Cliquez sur « Informations complémentaires » pour faire apparaître le nom de l'application, « Éditeur : Éditeur inconnu » et le bouton « Exécuter quand même ». Cliquez sur « Exécuter quand même » pour démarrer NPSeeker. Pour un même exécutable, cette demande n'apparaît normalement qu'une fois.
  • macOS : le système peut bloquer une application qui n'a pas été certifiée par Apple. Dans le terminal, exécutez xattr -dr com.apple.quarantine suivi du chemin du dossier NPSeeker (vous pouvez faire glisser le dossier dans le terminal pour insérer ce chemin). Autre possibilité : tentez de lancer NPSeeker, ouvrez ensuite « Réglages Système -> Confidentialité et sécurité » et sélectionnez « Ouvrir quand même » pour npseeker.
  • Linux : aucune autorisation supplémentaire n'est normalement nécessaire. Si le message "permission denied" apparaît, exécutez chmod +x bin/npseeker (ou chmod +x bin.arm64/npseeker sur arm64), puis réessayez.

0.4 Effectuer une première analyse avec l'interface graphique

Si vous préférez éviter la ligne de commande, NPSeeker propose une interface accessible depuis un navigateur. Sous Windows, double-cliquez sur npseeker.exe dans bin/. Sous macOS ou Linux, saisissez dans le terminal :

./bin/npseeker --gui

L'interface s'ouvre dans le navigateur. Pour effectuer un essai avec les données fournies, rendez-vous sur la page Design :

  • Target : choisissez dat/sample/S.aureus/, qui contient un génome de la bactérie Staphylococcus aureus.
  • Control : choisissez dat/sample/yeast/, qui contient les génomes de deux espèces de levures.
  • Probe length : conservez la valeur par défaut, 25, ainsi que les autres paramètres.
  • Cliquez sur "Check" pour vérifier les données et les paramètres, puis sur "Go" pour lancer le calcul.
  • Une fois l'analyse terminée, consultez la page Results pour examiner les sondes classées et leurs scores. Téléchargez les résultats à conserver.

L'interface fonctionne sur votre ordinateur : les fichiers génomiques ne sont pas envoyés à un site externe. Le chapitre 6 décrit les différentes pages et la procédure de fermeture de l'interface.

0.5 Effectuer une première analyse en ligne de commande

Vous pouvez analyser les mêmes données d'exemple directement dans le terminal :

Windows:          .\bin\npseeker.exe dat\sample\S.aureus\ dat\sample\yeast\
macOS, Linux:     ./bin/npseeker     dat/sample/S.aureus/ dat/sample/yeast/

Le calcul se termine en quelques secondes. Le programme affiche les sondes classées par score, par exemple (extrait) :

Best probes of cluster 0:
Rank Probe                     Exclus Purity UnFold Affini  Score     Tm
   1 CCGACTAACCCAGAGCGGACGAGCC  50.84  61.32 100.00  64.22  69.10  65.88
   2 GACCCGACTAACCCAGAGCGGACGA  50.84  61.40 100.00  63.68  68.98  64.24
...

Chaque ligne correspond à une sonde candidate. Probe désigne sa séquence nucléotidique ; Score est son score global, les meilleures valeurs figurant en premier. Les autres colonnes sont expliquées au chapitre 3. Une note (Note) en fin d'exécution vous rappelle d'utiliser -o pour enregistrer les résultats complets dans des fichiers :

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

Les fichiers seront placés dans result/ (section 3.2). Pour une nouvelle analyse, choisissez un autre dossier de sortie ou utilisez -w uniquement si vous acceptez de remplacer les résultats précédents. Pour travailler sur vos propres génomes, remplacez les dossiers d'exemple par vos données cibles et contrôles (chapitre 2).

1. Comment NPSeeker conçoit et évalue les sondes

NPSeeker reçoit des génomes cibles et contrôles et produit une liste classée de sondes candidates. Les cibles sont les organismes à détecter. Les contrôles sont ceux que les sondes doivent éviter, souvent des espèces proches qui risquent d'être confondues avec les cibles. L'analyse comporte quatre étapes :

  • Recherche de séquences communes : NPSeeker parcourt les génomes et extrait toutes les séquences de k nucléotides consécutifs, appelées k-mers. Par exemple, ACGTA contient trois 3-mers : ACG, CGT et GTA. Les k-mers présents dans chacun des génomes cibles deviennent des sondes candidates. Pour qu'une seule sonde puisse détecter toutes les cibles, sa séquence doit leur être commune. Comme l'ADN possède deux brins complémentaires, un k-mer et son complément inverse sont considérés comme équivalents.
  • Filtrage des candidates : NPSeeker élimine les séquences peu adaptées à l'utilisation comme sondes, notamment celles dont la composition en bases est trop déséquilibrée, qui comportent de longues répétitions d'un même nucléotide (par exemple AAAA), ou qui risquent de se replier sur elles-mêmes ou de s'apparier avec une autre copie de la sonde. Cela évite d'engager les calculs les plus coûteux sur des candidates peu prometteuses.
  • Comparaison avec les contrôles : NPSeeker recherche, dans les génomes contrôles, des correspondances exactes, des séquences proches ne différant que de quelques nucléotides et des occurrences de fragments plus courts.
  • Calcul des scores et classement : NPSeeker évalue chaque candidate selon quatre critères et en combine les scores.
ExclusivityExclusivité : présence dans les cibles et rareté dans les contrôles
PurityPureté : peu de séquences semblables ou de fragments communs dans les contrôles, donc moins de risque de liaison non voulue
UnfoldabilityFaible propension au repliement : la sonde reste accessible pour s'hybrider à sa cible
AffinityAffinité : force de liaison prédite à partir de l'énergie libre d'hybridation (énergie libérée lorsque la sonde se lie à sa cible)

Chaque composante et le score global sont compris entre 0 et 100 ; plus la valeur est élevée, plus la propriété prédite est favorable. Par défaut, les quatre composantes ont le même poids. Ces scores servent à sélectionner les candidates à soumettre à une validation expérimentale. Ils ne correspondent pas à des amplitudes de signal BioFET mesurées et ne garantissent pas les résultats d'une expérience.

Lorsque les génomes cibles diffèrent trop pour partager suffisamment de k-mers, NPSeeker les répartit en groupes et recherche des candidates séparément pour chaque groupe. Le chapitre 4 détaille ce regroupement et les modes de sortie. Les équations de score et les détails de l'algorithme figurent dans l'article.

2. Préparation des génomes cibles et contrôles

Les deux premiers arguments de la commande désignent, dans cet ordre, les données cibles et contrôles. Les options viennent ensuite :

./bin/npseeker <target> <control> [options]

Préparez un fichier FASTA par génome. FASTA est un format texte de séquences nucléotidiques ; ses fichiers portent généralement l'extension .fasta, .fna ou .fa. Les cibles et les contrôles peuvent être indiqués indépendamment par un dossier, une liste de fichiers ou un seul fichier FASTA.

2.1 Utiliser un dossier

Lorsqu'un dossier est fourni, NPSeeker lit les fichiers dont l'extension est .fasta, .fna ou .fa et traite chaque fichier comme un génome. Les extensions peuvent être entièrement en minuscules ou en majuscules (par exemple .FASTA). Les sous-dossiers ne sont pas parcourus.

./bin/npseeker targets/ controls/

Les fichiers compressés (.gz, .zst) présents dans un dossier ne sont pas pris en compte. Pour les utiliser, passez par une liste de fichiers.

2.2 Utiliser une liste de fichiers

Une liste de fichiers est un document texte contenant un chemin de fichier FASTA par ligne. Faites précéder son nom du caractère @ pour signaler à NPSeeker qu'il s'agit d'une liste :

./bin/npseeker @target.list @control.list

Exemple de contenu du fichier target.list :

# Trois génomes cibles
genomes/strain_A.fasta
genomes/strain_B.fna.gz
/data/others/strain_C.fa
  • Les lignes vides et celles commençant par # sont ignorées ; vous pouvez donc les utiliser pour ajouter des commentaires.
  • Les chemins relatifs sont interprétés à partir du dossier dans lequel vous exécutez NPSeeker, et non de celui qui contient la liste.
  • Les fichiers peuvent se trouver dans différents dossiers ou être des FASTA compressés au format gzip (.gz) ou zstd (.zst).
  • Avec -cluster-order input, l'ordre des fichiers dans la liste détermine leur ordre de traitement pendant le regroupement (chapitre 4).

Un fichier fourni sans @ et dont l'extension n'est pas une extension FASTA est également interprété comme une liste. Il est toutefois recommandé d'ajouter @ pour lever toute ambiguïté.

2.3 Utiliser un seul fichier FASTA

Si l'ensemble cible ou contrôle ne comprend qu'un génome, vous pouvez fournir son fichier FASTA directement, y compris s'il est compressé :

./bin/npseeker strain_A.fasta controls/

2.4 Contenu des fichiers FASTA et contrôles des entrées

  • Un fichier FASTA peut contenir plusieurs séquences, par exemple celles des chromosomes et plasmides. Toutes sont considérées comme un même génome.
  • NPSeeker reconnaît A, C, G et T, en majuscules comme en minuscules. Les autres lettres, telles que N, interrompent la séquence : aucun k-mer traversant leur position n'est pris en compte.
  • NPSeeker vérifie le format FASTA des fichiers d'entrée et s'arrête avec un message d'erreur si un fichier est introuvable ou invalide (section 7.2).
  • Un même fichier ne peut pas figurer à la fois parmi les cibles et les contrôles. NPSeeker signale ce doublon et interrompt l'analyse.

Le choix des génomes cibles et contrôles influence directement le classement des sondes. Privilégiez des contrôles représentant des organismes susceptibles d'être confondus avec vos cibles dans l'application envisagée, plutôt qu'un choix arbitraire d'espèces sans lien avec elles.

3. Lecture des résultats et choix des sondes

3.1 Résultats affichés à l'écran

Sans l'option -o, NPSeeker affiche les -top premières sondes (200 par défaut), avec les colonnes Rank, Probe, les quatre scores de composantes, Score et Tm. Avec -o, les résultats détaillés sont enregistrés dans des fichiers ; l'écran indique alors les fichiers créés. Ajoutez -v pour afficher les paramètres et le temps consacré à chaque étape du calcul.

3.2 Fichiers de résultats

Par exemple, -o result/ enregistre les résultats au format CSV (valeurs séparées par des virgules) par défaut :

cluster_N_probes.csvSondes candidates classées ; N désigne le numéro du groupe, à partir de 0
cluster.csvGroupe attribué à chaque génome
flag.csvParamètres utilisés pour cette analyse

L'option -format txt produit des tableaux alignés par des espaces, plus simples à lire directement. Les fichiers CSV s'importent facilement dans un tableur comme Excel ou dans d'autres programmes. Le nombre de fichiers de sondes dépend du mode single ou multi (chapitre 4).

Les colonnes des fichiers cluster_N_probes.csv sont les suivantes :

RankRang de la sonde
ProbeSéquence de la sonde, écrite de 5' vers 3'
TgtNombre d'occurrences dans les génomes cibles
CtlOccurrences exactes dans les génomes contrôles ; moins il y en a, mieux c'est
ExclusScore Exclusivity, calculé à partir de Tgt et Ctl
MMsScore des correspondances proches dans les contrôles ; une valeur faible est préférable
SubseqScore des fragments plus courts retrouvés dans les contrôles ; une valeur faible est préférable
PurityScore Purity, calculé à partir de MMs et Subseq
SelfAnPropension de la sonde à se replier sur elle-même (self-annealing) ; une valeur faible est préférable
DimerPropension à s'apparier avec une autre copie de la sonde (dimer) ; une valeur faible est préférable
UnFoldScore Unfoldability, calculé à partir de SelfAn et Dimer
AffiniScore Affinity, estimé à partir de l'énergie libre de liaison
ScoreMoyenne pondérée des quatre scores de composantes
TmTempérature de fusion (°C), à laquelle la moitié des duplex sonde-cible sont dissociés ; non prise en compte dans Score

Exclus, Purity, UnFold, Affini et Score sont compris entre 0 et 100 ; une valeur élevée est préférable. Si les cibles sont réparties entre plusieurs groupes, Tgt inclut également les correspondances proches trouvées dans les génomes cibles des autres groupes. Cette colonne ne représente donc pas toujours uniquement des occurrences exactes.

Le fichier cluster.csv contient trois colonnes : Group (target ou control), Cluster (numéro du groupe pour une cible, vide pour un contrôle) et File (nom du fichier). Le fichier flag.csv comporte les colonnes Option et Value, qui permettent de retrouver les paramètres de l'analyse.

Si le dossier de sortie n'existe pas, NPSeeker le crée. Un dossier existant mais vide peut aussi être utilisé. Si le dossier contient déjà des fichiers, le programme s'arrête sans les écraser. N'ajoutez -w que si vous souhaitez remplacer les anciens résultats : NPSeeker supprime les fichiers de résultats NPSeeker précédents (cluster_N_probes, cluster et flag), mais conserve les autres fichiers. Assurez-vous de ne plus avoir besoin des résultats antérieurs.

3.3 Choisir les sondes

Le score global constitue un premier critère de classement, mais ne doit pas être le seul. Selon votre application, examinez également :

  • Ctl : une valeur supérieure à zéro signifie qu'une séquence identique existe dans un génome contrôle. La sonde pourrait donc se lier à un organisme non ciblé, ce qui présente un risque de réaction croisée.
  • Tgt : un nombre élevé d'occurrences peut favoriser le signal, mais aussi révéler une région répétitive. Tgt ne permet pas de prédire directement l'intensité du signal.
  • Purity et UnFold : ces scores permettent de comparer les risques de liaison non spécifique et de repliement de la sonde sur elle-même.
  • Tm : si votre essai impose une température particulière ou utilise plusieurs sondes, comparez leurs températures de fusion. Il est préférable que les sondes employées ensemble aient des valeurs de Tm proches.

Vous pouvez également soumettre une sonde à NCBI BLAST afin de rechercher des séquences similaires chez d'autres organismes, ou à UNAFold (mfold) pour examiner les structures de repliement possibles. Des liens vers ces services figurent sur la page Results. Attention : ils transmettent la séquence sélectionnée à un site externe (section 6.2). L'adéquation d'une sonde à une plateforme BioFET donnée doit, dans tous les cas, être vérifiée dans les conditions expérimentales prévues.

4. Regroupement des cibles et modes single et multi

Lorsque les génomes cibles ont trop peu de k-mers communs, NPSeeker les répartit en groupes (clusters). Il examine les génomes un à un. Un génome n'est ajouté au groupe en cours que si tous les membres de ce groupe, y compris le nouveau génome, possèdent encore au moins -min-shared k-mers en commun. Sinon, son traitement est reporté à un autre groupe. Ces groupes servent à la recherche de sondes candidates : ce ne sont pas des classifications évolutives ou phylogénétiques.

L'option -cluster-order fixe l'ordre dans lequel les génomes cibles sont examinés :

  • auto (par défaut) : détermine un ordre reproductible à partir des k-mers partagés entre génomes. Pour un même ensemble de génomes, changer l'ordre des fichiers d'entrée ne modifie pas les groupes obtenus.
  • input : conserve l'ordre fourni par l'utilisateur, par exemple celui de la liste de fichiers. Choisissez ce mode si vous voulez qu'un génome de référence serve de point de départ au premier groupe.

La valeur par défaut de -min-shared est 1 : un génome rejoint un groupe dès lors qu'au moins un k-mer reste commun à tous ses membres. Les cibles forment donc souvent un seul groupe. Augmenter ce seuil peut créer davantage de groupes et modifier les candidates disponibles pour chacun.

Lorsque les cibles forment plusieurs groupes, -mode détermine le classement et l'enregistrement des sondes candidates :

  • single (par défaut) : rassemble les candidates de tous les groupes dans un classement unique et conserve les -top premières sondes dans cluster_0_probes.csv. Plusieurs sondes bien classées peuvent provenir du même groupe.
  • multi : classe séparément les candidates de chaque groupe et conserve au maximum -top sondes par groupe dans cluster_0_probes.csv, cluster_1_probes.csv, etc. Ce mode convient pour rechercher des sondes destinées à chacun des groupes de cibles.

En mode multi, choisir des sondes dans chaque groupe permet de constituer un ensemble de candidates couvrant, du point de vue du calcul, tous les groupes cibles. Leur efficacité réelle reste à confirmer expérimentalement. Le fichier cluster.csv indique la composition des groupes. Si aucune candidate d'un groupe ne passe les filtres, NPSeeker affiche un avertissement et enregistre tout de même les résultats des autres groupes.

5. Options et paramètres

Les options se placent après les arguments target et control. Lorsqu'une option attend une valeur, séparez-les par une espace (par exemple -k 31). Les commutateurs, comme -v, -w et --gui, ne prennent pas de valeur. Certaines options possèdent une forme courte et une forme longue (par exemple -k et -kmer), équivalentes. Les nombres peuvent être écrits en notation scientifique : 1e7 signifie 10 000 000. Sur la ligne de commande, les décimales s'écrivent avec un point (par exemple -c 0.5). Les sections suivantes reprennent les rubriques de -help. Le nom entre parenthèses dans chaque titre correspond à une rubrique de l'aide. L'annexe A en donne un récapitulatif.

5.1 Longueur des sondes et ressources de calcul (General settings)

-k, -kmer [entier, de 5 à 256 ; défaut : 25]

Définit la longueur des sondes en nucléotides. Choisissez-la en fonction des besoins de votre essai. Lorsque k augmente, il devient plus difficile de trouver des séquences identiques de cette longueur dans des génomes cibles très différents ; davantage de groupes peuvent alors être nécessaires. Le temps de calcul dépend surtout de la taille des génomes et du nombre de candidates : des sondes plus longues ne sont pas nécessairement plus lentes à concevoir (voir la figure 4 de l'article).

-t, -threads [entier ; défaut : 0]

Définit le nombre de threads de calcul exécutés en parallèle. La valeur 0 utilise tous les threads matériels disponibles. Réduisez ce nombre si l'ordinateur doit aussi servir à d'autres tâches.

-m, -memory [taille ; défaut : moitié de la RAM, plafonnée à 8G]

Définit le budget mémoire des principales étapes de calcul, par exemple avec -m 8G ou -m 512M. Sans unité, la valeur est interprétée en GiB. Un budget plus faible entraîne davantage de traitements par lots et peut ralentir l'analyse, mais ne modifie pas les résultats. La mémoire nécessaire au chargement des lots de candidates (-b) et aux autres données d'exécution s'ajoute à ce budget (section 5.5).

5.2 Sortie et journal d'exécution (Output)

-o, -out-dir [dossier ; défaut : aucun fichier enregistré]

Indique le dossier dans lequel les résultats seront enregistrés (section 3.2). Sans -o, les résultats s'affichent à l'écran, avec moins de colonnes. Précisez un dossier de sortie pour conserver, comparer ou reproduire une analyse.

-w, --overwrite

Autorise la réutilisation d'un dossier -o qui n'est pas vide. Les anciens fichiers de résultats NPSeeker qu'il contient sont supprimés avant l'écriture des nouveaux ; les fichiers sans rapport sont conservés (section 3.2).

-top [entier ; défaut : 200]

Définit le nombre de sondes les mieux classées à conserver dans chaque classement. Augmentez-le pour examiner davantage de candidates. Une valeur très élevée peut produire des fichiers volumineux et consommer plus de mémoire et de temps. Choisissez-la selon vos besoins.

-format [csv ou txt ; défaut : csv]

Définit le format des fichiers. csv correspond à des valeurs séparées par des virgules, faciles à importer dans un tableur ou un autre programme ; txt produit un tableau aligné par des espaces, pour une lecture directe.

-v, --verbose

Affiche des informations supplémentaires : données d'entrée, paramètres, étapes du calcul et temps consacré à chacune. Cette option est utile pour suivre les analyses longues ou rechercher l'origine d'un problème. Les analyses lancées depuis l'interface graphique utilisent toujours ce journal détaillé.

5.3 Regroupement et classement (Target clustering, Probe ranking)

-cluster-order [auto ou input ; défaut : auto]

Détermine l'ordre de traitement des génomes cibles lors du regroupement. auto ne dépend pas de l'ordre des fichiers d'entrée ; input reprend l'ordre fourni. Voir le chapitre 4 pour les détails et les cas d'utilisation.

-min-shared [entier ; défaut : 1]

Définit le nombre minimal de k-mers devant rester communs à tous les génomes d'un groupe. Augmenter ce seuil entraîne généralement davantage de groupes, mais ne garantit pas que chacun fournira des sondes adaptées (chapitre 4).

-mode [single ou multi ; défaut : single]

Les deux modes ne diffèrent que lorsque les cibles sont réparties en plusieurs groupes. single classe toutes les candidates ensemble ; multi produit un classement distinct pour chaque groupe. Le chapitre 4 aide à choisir le mode.

-weights [KEY=WEIGHT séparés par des virgules ; défaut : 1 par composante]

Modifie le poids des quatre composantes dans le score global : exclusivité (exc), pureté (pur), faible propension au repliement (unf) et affinité (aff). Par exemple :

-weights exc=2,pur=2

Cette commande double le poids de l'exclusivité et de la pureté, tandis que ceux de unf et aff restent égaux à 1. Le score global est calculé ainsi :

Score = (w_exc*Exclus + w_pur*Purity + w_unf*UnFold + w_aff*Affini)
        / (w_exc + w_pur + w_unf + w_aff)

Les poids peuvent être nuls, mais pas négatifs, et au moins un doit être strictement positif. Une composante de poids nul est quand même calculée, mais elle n'entre pas dans Score. Augmenter le poids d'une composante modifie le classement ; cela n'élimine pas les candidates qui obtiennent un faible score pour cette composante.

-mm, -mismatch-cutoff [entier ; défaut : partie entière de k/10]

Fixe le nombre maximal de nucléotides différents autorisés entre une sonde et une séquence des génomes contrôles pour que celle-ci soit considérée comme une correspondance proche lors du calcul de la pureté. Une tolérance plus élevée permet de détecter davantage de correspondances proches, mais peut augmenter fortement le temps de calcul et l'utilisation de la mémoire. Ce seuil doit rester inférieur à la longueur de la sonde.

5.4 Filtrage des sondes candidates (Candidate filtering)

NPSeeker filtre les candidates avant de procéder aux comparaisons, plus coûteuses, avec les génomes contrôles. Si les critères sont trop stricts, aucune candidate ne peut subsister. Vous pouvez alors assouplir un ou plusieurs des seuils suivants.

-max-homopolymer [entier ; défaut : 3]

Un homopolymère est une suite de nucléotides identiques, comme AAAA. Cette option fixe sa longueur maximale autorisée : la valeur 3 accepte AAA, mais rejette toute candidate contenant AAAA ou une suite plus longue. Augmenter ce seuil conserve davantage de candidates contenant des répétitions d'une même base.

-c, -min-complexity [nombre entre 0 et 1 ; défaut : 0.5]

Fixe le seuil minimal du score de complexité des séquences. Plus les quatre nucléotides sont représentés de manière équilibrée, plus le score est élevé. Une candidate doit dépasser ce seuil pour être retenue.

-e, -min-entropy [nombre entre 0 et 2 ; défaut : 1.5]

Fixe le seuil minimal du score d'entropie de la séquence. Ce score mesure la variété de la séquence : les motifs répétitifs, comme ACACAC, ont une faible entropie. Une candidate doit dépasser le seuil pour être retenue. Pour les sondes courtes, les scores maximaux possibles de complexité et d'entropie sont plus faibles. Si le seuil fixé dépasse le maximum possible pour la longueur choisie, NPSeeker affiche une erreur et indique cette valeur maximale.

-prefilter [T ou F ; défaut : T]

Indique si les candidates doivent subir un premier filtrage selon leur propension au repliement, avant l'examen des génomes contrôles. T écarte les candidates dont le score Unfoldability est inférieur à -min-unfold, afin de limiter le nombre de comparaisons. F désactive ce filtrage préalable ; le score Unfoldability est néanmoins calculé pour chaque candidate.

-min-unfold [nombre entre 0 et 100 ; défaut : 75]

Fixe le seuil Unfoldability du filtrage préalable. Abaisser ce seuil conserve plus de candidates susceptibles de se replier et peut augmenter la charge des comparaisons suivantes. Si aucune candidate d'un lot n'atteint le seuil, NPSeeker n'applique pas ce préfiltrage à ce lot. Par exemple, la sonde pour bactéries à Gram positif évaluée expérimentalement dans l'article a un score Unfoldability de 72,54 : utilisez -min-unfold 70 pour reproduire son classement (chapitre 8).

5.5 Options avancées (Advanced)

Les valeurs par défaut conviennent à la plupart des utilisations.

-b, -batch-size [entier ; défaut : 1e7]

Définit le nombre de k-mers candidats chargés et filtrés à la fois. Pour k = 25, chaque candidate occupe environ 170 octets : un lot de 10 millions de candidates, la valeur par défaut, nécessite donc environ 1,58 GiB en plus du budget mémoire fixé par -m. Diminuez cette option si la mémoire disponible est limitée ; des lots plus petits peuvent toutefois augmenter la durée du calcul.

-s, -min-subseq [entier ; défaut : 7]

Définit la longueur minimale des fragments de sonde pris en compte dans le score Purity. À utiliser avec -subseq-step.

-subseq-step [entier ; défaut : partie entière supérieure de k/10]

Définit de combien la longueur des fragments diminue à chaque étape du calcul de Purity. Par exemple, pour k = 25, le pas par défaut est 3 : les longueurs examinées sont 22, 19, 16, 13, 10 et 7. Un pas plus petit conduit à examiner davantage de longueurs et augmente le travail de comparaison.

-tmp-dir [dossier ; défaut : dossier temporaire du système]

Définit le dossier de stockage des fichiers intermédiaires. NPSeeker y crée son propre sous-dossier et le supprime à la fin d'une exécution normale ou interrompue par Ctrl-C. Si le disque système manque d'espace libre, choisissez un dossier situé sur un autre disque.

5.6 Interface graphique et aide (Graphical interface)

--guiLance l'interface graphique locale au lieu d'effectuer directement une analyse en ligne de commande
-gui-port [entier]Port d'écoute (nombre après les deux-points dans l'URL) ; par défaut, choisi automatiquement
--no-browserAffiche l'URL de l'interface sans ouvrir le navigateur
--tabOuvre l'interface dans un onglet du navigateur
-hAffiche l'aide abrégée

L'option --gui ne peut être combinée qu'avec -gui-port, --no-browser et --tab. Réglez les paramètres d'analyse, tels que -k, dans l'interface : leur présence sur la ligne de commande avec --gui provoque une erreur. Voir le chapitre 6.

6. Interface graphique

NPSeeker démarre un serveur web local, accessible uniquement depuis votre ordinateur (adresse 127.0.0.1), afin de proposer une interface dans le navigateur. Les calculs sont réalisés par NPSeeker lui-même : les fichiers génomiques ne sont pas envoyés à un service externe. Avec les mêmes paramètres, l'interface graphique et la ligne de commande produisent les mêmes résultats.

6.1 Démarrer l'interface et s'y connecter

  • Windows : double-cliquez sur npseeker.exe dans le dossier bin/, ou lancez .\bin\npseeker.exe --gui dans l'invite de commandes. Une fenêtre de console (fenêtre noire affichant les messages du programme) apparaît. Laissez-la ouverte tant que vous utilisez l'interface.
  • macOS, Linux : exécutez ./bin/npseeker --gui dans un terminal.

NPSeeker ouvre le navigateur et affiche l'adresse de l'interface, par exemple :

http://127.0.0.1:53817/?t=1a2b3c...

La partie située après ?t= est un jeton d'accès propre à cette session. Si le navigateur ne s'ouvre pas automatiquement, copiez-y l'adresse complète. Ne communiquez pas ce lien à une personne non autorisée, car il contient le jeton d'accès.

Par défaut, l'interface s'ouvre dans une fenêtre distincte : les navigateurs comme Edge et Chrome l'affichent en mode application, sans barre d'adresse, tandis que Firefox ouvre une nouvelle fenêtre. L'option --tab permet de l'ouvrir plutôt dans un onglet du navigateur par défaut.

6.2 Pages principales

DesignChoisissez Target, Control, le dossier de sortie (facultatif) et la longueur de la sonde. Vous pouvez sélectionner un dossier ou des fichiers FASTA individuels, y compris des fichiers compressés situés à différents emplacements. "Tick all" sélectionne tous les fichiers d'un dossier ; "Pick folder" et "Pick files" utilisent les boîtes de dialogue du système. Les autres paramètres se trouvent dans un panneau déroulant ; un champ vide conserve sa valeur par défaut. "Check" vérifie les entrées et les paramètres, tandis que "Go" lance le calcul.
RunAffiche l'étape en cours, la progression et le journal d'exécution. "Cancel" interrompt le calcul.
ResultsAffiche les sondes classées, leurs séquences et leurs scores. Cliquez sur l'en-tête d'une colonne pour trier les résultats ; Rank conserve le rang attribué initialement par NPSeeker. Cliquez sur une sonde pour afficher notamment son complément inverse et sa température de fusion, ou pour copier sa séquence. Vous pouvez télécharger les fichiers un par un ou les réunir dans une archive zip.
HelpPermet de consulter ce manuel et de changer de langue (anglais par défaut ; le dernier choix est mémorisé).
AboutPrésente le logiciel, l'article, les auteurs et les coordonnées.

La page Results propose également deux liens vers des services externes :

  • BLAST at NCBI : lance une recherche de séquences similaires dans d'autres organismes à partir de la sonde sélectionnée.
  • Fold at UNAFold : transmet la séquence à UNAFold (mfold) pour prédire son repliement, avec les paramètres par défaut du formulaire en ligne (37 °C, 1 M Na+).

Ces deux fonctions nécessitent une connexion Internet et transmettent la séquence de la sonde sélectionnée à un site externe. Avant de les utiliser pour une séquence non publiée, vérifiez que cette transmission est autorisée.

Si aucun dossier de sortie n'a été spécifié, l'interface conserve les résultats dans un dossier temporaire sur le disque local. Ces fichiers seront supprimés à la fermeture de l'interface. Téléchargez donc les résultats à conserver avant de quitter NPSeeker.

6.3 Boutons Close et Exit, et conservation des résultats

  • "Close" ferme uniquement la page du navigateur : NPSeeker continue de fonctionner, ainsi que tout calcul en cours. Pour revenir à l'interface, ouvrez de nouveau l'adresse affichée dans la console.
  • "Exit" arrête l'interface et interrompt tout calcul en cours. Fermer la console ou appuyer sur Ctrl-C met également fin au programme.
  • Si toutes les pages de l'interface restent fermées pendant plus de cinq minutes et qu'aucun calcul n'est en cours, NPSeeker se termine automatiquement. Les résultats temporaires non téléchargés sont supprimés.

Lorsque vous cliquez sur "Exit" ou "Close", l'interface demande confirmation. Elle signale également les calculs en cours et les résultats temporaires qui n'ont pas encore été téléchargés.

Si vous avez choisi un dossier de sortie, les résultats y sont conservés. Une nouvelle analyse utilisant ce même dossier remplacera les précédents fichiers de résultats de NPSeeker, mais pas les autres fichiers.

Vous pouvez choisir le thème Auto, Dark ou Light. En mode Auto, l'interface reprend le thème clair ou sombre du système d'exploitation.

6.4 Utiliser l'interface sur un serveur distant

Si NPSeeker s'exécute sur un serveur distant, un tunnel SSH (connexion chiffrée qui redirige un port de votre ordinateur vers le serveur) permet d'accéder à l'interface depuis votre navigateur local. Sur le serveur, lancez NPSeeker en indiquant un port :

./bin/npseeker --gui --no-browser -gui-port 53817

Sur votre ordinateur, ouvrez un terminal et établissez le tunnel :

ssh -L 53817:127.0.0.1:53817 compte@serveur

Tant que la connexion SSH reste ouverte, saisissez dans votre navigateur local l'adresse complète affichée par le serveur. Vous pouvez choisir un autre port du côté de votre ordinateur, par exemple :

ssh -L 9000:127.0.0.1:53817 compte@serveur

Dans ce cas, remplacez l'adresse de base par http://127.0.0.1:9000/ tout en conservant le jeton ?t=... de l'URL fournie par le serveur.

En utilisation distante, l'explorateur de fichiers intégré à NPSeeker présente les dossiers du serveur. Les commandes "Pick folder" et "Pick files" ouvrent aussi les boîtes de dialogue sur le serveur : elles ne sont pas utilisables si celui-ci ne dispose pas d'un bureau graphique. Utilisez alors l'explorateur de fichiers intégré à l'interface.

6.5 Emplacement des fichiers de configuration

NPSeeker mémorise les dossiers récemment utilisés (recent.txt), le dernier emplacement sélectionné (lastpick.txt), le thème de l'interface (theme.txt) et la langue de la page Help (help-lang.txt). Ces petits fichiers sont stockés dans :

Linux~/.config/npseeker/
macOS~/Library/Application Support/npseeker/
Windows%AppData%\npseeker\

Les fichiers intermédiaires du calcul se trouvent dans le dossier temporaire du système ou celui indiqué par -tmp-dir, et non à ces emplacements.

7. Performances et résolution des problèmes

7.1 Mémoire, durée du calcul et fichiers temporaires

  • Mémoire : -m fixe le budget des principales étapes de calcul, mais les lots de candidates chargés par -b et les autres données du programme consomment aussi de la mémoire. Si celle-ci manque, diminuez à la fois -m et -b.
  • Threads : -t 0 utilise tous les threads matériels disponibles. Diminuez cette valeur si l'ordinateur sert également à d'autres tâches.
  • Durée : elle dépend de la taille des génomes, du nombre de candidates communes, de -mm, de la mémoire, du matériel et de la vitesse du disque. Augmenter k ne ralentit pas nécessairement le calcul. L'option -v permet de mesurer la durée de chaque étape.
  • Fichiers temporaires : NPSeeker crée des fichiers intermédiaires dont la taille dépend des données et du budget mémoire. Un budget plus faible peut nécessiter davantage d'espace disque temporaire. Prévoyez suffisamment de place ; ces fichiers sont supprimés après une exécution normale ou un arrêt par Ctrl-C.

7.2 Messages d'erreur courants

Les erreurs d'options ou de paramètres commencent par "npseeker:". Les erreurs de fichiers d'entrée, de sortie ou d'exécution commencent par "Error:". Voici quelques exemples et les solutions possibles. Le terme target peut être remplacé par control lorsque l'erreur concerne un génome contrôle.

  • Error: target: no FASTA file (*.fasta, *.fna or *.fa) in the folder ...
    Aucun fichier portant l'une de ces extensions n'a été trouvé dans le dossier. Pour les fichiers compressés, utilisez une liste de fichiers (section 2.2).
  • Error: target: "..." is not found
    Le chemin est incorrect. Les chemins relatifs sont interprétés à partir du dossier dans lequel vous lancez NPSeeker.
  • Error: target: "..." is not a FASTA file: ...
    Le fichier n'est pas reconnu comme FASTA ; le texte après les deux-points indique la raison.
  • Error: target: the FASTA file "...", listed in "...", is not found
    Un fichier mentionné dans la liste est introuvable.
  • Error: target and control: ...; a genome cannot be both a target and a control
    Un même fichier figure dans les deux ensembles.
  • Error: -o: the folder "..." already exists and is not empty; give -w ...
    Le dossier de sortie n'est pas vide. Choisissez-en un autre ou utilisez -w après avoir vérifié que les résultats précédents peuvent être remplacés.
  • npseeker: option -mm: must be less than the probe length (-k)
    Le seuil de mésappariements -mm doit être inférieur à la longueur de la sonde.
  • npseeker: option -c: no probe of 8 nt has a complexity score above 0.431 ...
    Le seuil choisi dépasse le maximum possible pour cette longueur de sonde (0,431 dans cet exemple) ; diminuez-le (section 5.4).
  • Error: -tmp-dir: cannot create the folder "...": ...
    Le dossier temporaire n'a pas pu être créé. Vérifiez le chemin et les droits d'écriture.

7.3 Sortie standard et sortie d'erreur

Les messages affichés dans un terminal passent par deux canaux : la sortie standard (stdout) et la sortie d'erreur (stderr). En temps normal, les deux sont visibles au même endroit. Si vous redirigez la sortie vers un fichier, par exemple en ajoutant > out.txt à la commande, seule la sortie standard est écrite dans ce fichier ; la sortie d'erreur reste affichée à l'écran.

NPSeeker écrit les résultats, le journal de -v et les erreurs sur stdout. Les remarques commençant par Note:, les avertissements commençant par Warning: et les barres de progression passent par stderr. La redirection permet ainsi d'enregistrer les résultats sans les messages de progression, qui restent visibles dans le terminal.

7.4 Absence de sondes candidates ou calcul trop lent

Si aucune sonde candidate ne passe les filtres, NPSeeker affiche :

Warning: no probe passed the filters; relax the thresholds
         (-max-homopolymer, -c, -e, -min-unfold) to let probes pass.

Vous pouvez assouplir successivement -min-unfold, -c, -e et -max-homopolymer (section 5.4). Si les génomes cibles partagent très peu de k-mers, essayez de réduire -k ou d'ajuster -min-shared et -mode (chapitre 4). Avec -v, vous pouvez voir combien de candidates restent après chaque étape et combien de temps celle-ci a pris.

Si le calcul est lent, vérifiez d'abord que la mémoire disponible est suffisante pour -m, les lots -b et les autres données d'exécution. Quand la mémoire manque, le système peut transférer des données sur le disque, ce qui ralentit beaucoup le calcul. Si -mm est élevé, comparez les performances avec sa valeur par défaut. Sur de grands jeux de données, examinez aussi la vitesse du disque et l'espace disponible dans le dossier temporaire.

8. Exemples d'utilisation

Les exemples ci-dessous utilisent la syntaxe macOS et Linux. Sous Windows, remplacez ./bin/npseeker par .\bin\npseeker.exe et utilisez le séparateur \ plutôt que / dans les chemins. Chaque exemple peut être lancé séparément. Si result/ contient déjà des résultats, choisissez un nouveau dossier de sortie ou ajoutez -w uniquement si vous acceptez de remplacer les anciens résultats.

Analyse de base avec enregistrement dans result/ :

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

Utiliser une liste de génomes cibles et conserver l'ordre de regroupement :

./bin/npseeker @target.list controls/ -cluster-order input -o result/

Concevoir des sondes de 31 nucléotides avec 32 threads et 16 GiB de mémoire :

./bin/npseeker targets/ controls/ -k 31 -t 32 -m 16G -o result/

Donner davantage de poids à l'exclusivité et à la pureté dans le score global :

./bin/npseeker targets/ controls/ -weights exc=2,pur=2 -o result/

Rechercher des sondes distinctes pour plusieurs groupes cibles :

./bin/npseeker targets/ controls/ -min-shared 20000 -mode multi -o result/

Reproduire les classements de sondes bactériennes du tableau 3 de l'article (avec les paramètres de l'étude, qui diffèrent des valeurs par défaut ; les jeux de données sont à télécharger séparément, voir la section 0.2) :

./bin/npseeker dat/datasets/GP/ dat/datasets/GN/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GP_probes/
./bin/npseeker dat/datasets/GN/ dat/datasets/GP/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GN_probes/

La valeur -min-unfold 70 permet de conserver la sonde pour bactéries à Gram positif évaluée expérimentalement, dont le score Unfoldability est de 72,54. Sous macOS et Linux, le caractère \ à la fin d'une ligne permet de poursuivre la commande à la ligne suivante. Sous Windows, utilisez ^ dans l'invite de commandes et l'accent grave ` dans PowerShell, ou saisissez la commande sur une seule ligne.

Une partie du jeu de données utilisé dans l'article provient de l'ATCC Genome Portal, dont les conditions d'utilisation interdisent la redistribution. Le dossier dat/datasets/ contient donc des données correspondantes issues du NCBI ; le fichier dat/datasets/sources.txt indique, fichier par fichier, la correspondance avec le jeu de données de l'article. Avec ces données, les séquences et les rangs des deux sondes du tableau 3 sont reproduits à l'identique, mais le nombre de sondes candidates, le nombre d'occurrences et les scores diffèrent légèrement. L'un de ces génomes, S. enterica ATCC 43976, n'existe au NCBI que sous forme d'assemblage incomplet (une partie de son ARNr 23S manque). Si on le laisse de côté lorsque GN est la cible (en le décochant dans l'interface graphique, ou en utilisant la liste de fichiers @dat/datasets/GN-without-43976.list en ligne de commande), le nombre de sondes candidates revient à 65, et les 8 premières sondes du tableau supplémentaire S3 sont aussi identiques à celles de l'article.

Enregistrer davantage de sondes dans un tableau texte facile à lire :

./bin/npseeker targets/ controls/ -format txt -top 1000 -o result/
