Manual do usuário do NPSeeker

Versão 1.5.42

Apresentação do NPSeeker

O NPSeeker (Nucleic Acid Probe Seeker) é um programa para projetar sondas de ácidos nucleicos a partir de sequências genômicas. Seu principal objetivo é selecionar sondas para biossensores, como os BioFETs (transistores de efeito de campo usados em biossensoriamento). Uma sonda de ácido nucleico é uma sequência curta de DNA capaz de se hibridizar ao DNA de um organismo que se deseja detectar ou identificar.

O NPSeeker recebe dois conjuntos de genomas: os genomas-alvo (dos organismos a detectar) e os genomas de controle (dos organismos que não devem ser detectados). Primeiro, identifica sequências de DNA presentes em todos os genomas-alvo. Em seguida, avalia a semelhança dessas sequências com os controles, sua capacidade prevista de ligação ao alvo e sua tendência a se dobrar sobre si mesmas. Por fim, classifica as sondas candidatas conforme suas pontuações. O comprimento das sondas pode variar de 5 a 256 nucleotídeos.

AutoresHao-Yu Peng, Hui Zhi Gan, et al.

Sobre este manual

Se esta é sua primeira experiência com o NPSeeker, comece pelo capítulo 0. Caso prefira a interface gráfica, depois de concluir as seções 0.1 a 0.3 você pode ir diretamente à seção 0.4. O capítulo 2 explica como preparar seus próprios arquivos de genomas, enquanto o capítulo 5 apresenta os parâmetros do programa.

O programa também oferece ajuda integrada: -h mostra as opções mais utilizadas, e -help apresenta todas as opções. Este manual complementa essa ajuda com instruções passo a passo, exemplos e orientações práticas. Está disponível em texto simples (UserManual-pt-BR.txt) e HTML (UserManual-pt-BR.html). Você também pode acessá-lo pela página Help da interface gráfica.

0. Primeiros passos

Salvo indicação em contrário, os comandos deste manual seguem a sintaxe do macOS e do Linux. Quando necessário, são apresentadas as alternativas para Windows.

Se você nunca utilizou um programa pela linha de comando, siga este capítulo na ordem apresentada.

0.1 Baixar a versão adequada

Baixe no site do NPSeeker ou no GitHub o arquivo compactado correspondente ao seu sistema operacional. Há arquivos separados para Windows, macOS e Linux, cada um com executáveis para duas arquiteturas de processador:

x86_64Maioria dos processadores Intel e AMD
arm64Macs com chips Apple da série M e outros computadores ARM

Se você não souber qual é a arquitetura do seu computador:

  • Windows: Abra "Configurações -> Sistema -> Sobre". Em "Tipo de sistema", x64 corresponde a x86_64 e ARM64 corresponde a arm64.
  • macOS: Abra "menu Apple -> Sobre Este Mac". Macs com chips Apple da série M usam arm64; Macs com processadores Intel usam x86_64.
  • Linux: Abra um terminal, digite uname -m e pressione Enter. O resultado será x86_64 ou aarch64 (equivalente a arm64).

0.2 Descompactar o arquivo

Extraia o arquivo baixado para a pasta de sua preferência:

  • Windows: Clique com o botão direito no arquivo compactado e escolha "Extrair tudo".
  • macOS: Clique duas vezes no arquivo.
  • Linux: Em um terminal, execute tar xzf seguido do nome do arquivo compactado.

A pasta NPSeeker extraída contém:

bin/Executável x86_64: npseeker (npseeker.exe no Windows)
bin.arm64/Executável arm64
doc/Manuais do usuário
dat/sample/Dados de exemplo para a primeira execução

Os genomas bacterianos usados no artigo do NPSeeker (Gram-negativas GN e Gram-positivas GP) são um download separado (NPSeeker-1.5.42-datasets.zip ou .tar.gz). Você pode extraí-lo e mover a pasta datasets que ele contém (em NPSeeker/dat/) para a pasta dat do programa, o que permite executar os exemplos de comandos do capítulo 8 exatamente como estão escritos.

O NPSeeker não exige instalação nem conexão com a internet para análises locais. Os comandos deste manual usam o executável x86_64 da pasta bin/. Em computadores arm64, substitua bin por bin.arm64 nos comandos.

0.3 Verificar se o NPSeeker funciona

Abra uma janela de linha de comando e entre na pasta do NPSeeker que você extraiu:

  • Windows: Abra a pasta NPSeeker no Explorador de Arquivos. Digite cmd na barra de endereços e pressione Enter. O Prompt de Comando será aberto diretamente nessa pasta. Você também pode usar o PowerShell com os mesmos comandos.
  • macOS: Abra o "Terminal" (Aplicativos -> Utilitários). Digite cd seguido de um espaço, arraste a pasta NPSeeker para a janela do Terminal e pressione Enter.
  • Linux: Abra um terminal e use cd para acessar a pasta NPSeeker.

Em seguida, digite o comando correspondente ao seu sistema e pressione Enter:

Windows:          .\bin\npseeker.exe -h
macOS, Linux:     ./bin/npseeker -h

Se o programa mostrar o logotipo, a sintaxe de uso e as principais opções, está pronto para ser utilizado.

Na primeira execução, o sistema operacional pode exibir um aviso de segurança porque o executável baixado não possui assinatura digital.

Antes de permitir a execução, confirme que o NPSeeker foi obtido do site ou do GitHub indicados em "Apresentação do NPSeeker". Não ignore alertas de segurança de programas de origem desconhecida.

  • Windows: Pode aparecer uma janela azul do Microsoft Defender SmartScreen com o aviso "O Windows protegeu seu computador" e, inicialmente, apenas o botão "Não executar". Clique em "Mais informações" para visualizar o nome do aplicativo, o editor desconhecido e o botão "Executar assim mesmo". Clique neste último para iniciar o NPSeeker. Normalmente, essa confirmação é solicitada apenas uma vez para o mesmo executável. Os textos podem variar conforme a versão do Windows.
  • macOS: O sistema pode bloquear um aplicativo que não foi autenticado pela Apple. No Terminal, execute xattr -dr com.apple.quarantine seguido do caminho da pasta NPSeeker (você pode arrastar a pasta para o Terminal para inserir o caminho). Como alternativa, tente abrir o NPSeeker e depois acesse "Ajustes do Sistema -> Privacidade e Segurança" e escolha "Abrir Mesmo Assim" para npseeker.
  • Linux: Normalmente, nenhuma etapa adicional é necessária. Se aparecer "permission denied", execute chmod +x bin/npseeker (ou chmod +x bin.arm64/npseeker no arm64) e tente novamente.

0.4 Fazer a primeira análise pela interface gráfica

Se preferir não usar a linha de comando, o NPSeeker oferece uma interface acessível pelo navegador. No Windows, clique duas vezes em npseeker.exe na pasta bin/. No macOS ou Linux, digite no terminal:

./bin/npseeker --gui

A interface será aberta no navegador. Para testá-la com os dados incluídos, acesse a página Design:

  • Target: Selecione dat/sample/S.aureus/, que contém um genoma da bactéria Staphylococcus aureus.
  • Control: Selecione dat/sample/yeast/, que contém genomas de duas espécies de leveduras.
  • Probe length: Mantenha o valor padrão de 25 e não altere os demais parâmetros.
  • Clique em "Check" para validar os dados e os parâmetros. Depois, clique em "Go" para iniciar a análise.
  • Quando a execução terminar, abra a página Results para examinar as sondas classificadas e suas pontuações. Baixe os arquivos que desejar guardar.

A interface funciona em seu próprio computador e não envia os arquivos de genomas a um site externo. Consulte o capítulo 6 para conhecer suas páginas e saber como encerrá-la.

0.5 Fazer a primeira análise pela linha de comando

Os mesmos dados de exemplo podem ser analisados diretamente pela linha de comando:

Windows:          .\bin\npseeker.exe dat\sample\S.aureus\ dat\sample\yeast\
macOS, Linux:     ./bin/npseeker     dat/sample/S.aureus/ dat/sample/yeast/

A execução deve terminar em poucos segundos. A tela mostrará uma lista de sondas ordenadas por pontuação, semelhante a este trecho:

Best probes of cluster 0:
Rank Probe                     Exclus Purity UnFold Affini  Score     Tm
   1 CCGACTAACCCAGAGCGGACGAGCC  50.84  61.32 100.00  64.22  69.10  65.88
   2 GACCCGACTAACCCAGAGCGGACGA  50.84  61.40 100.00  63.68  68.98  64.24
...

Cada linha representa uma sonda candidata. Probe é sua sequência de DNA, e Score é a pontuação geral; as sondas com maiores pontuações aparecem primeiro. O capítulo 3 explica as outras colunas. Ao final da execução, uma mensagem Note lembra que é necessário usar -o para salvar os resultados completos em arquivos. Por exemplo:

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

Os arquivos serão gravados em result/ (seção 3.2). Na próxima análise, escolha outra pasta de saída ou acrescente -w somente se quiser substituir os resultados anteriores. Para analisar seus próprios genomas, troque as duas pastas de exemplo pelos dados de alvo e controle (capítulo 2).

0.6 Consultar a ajuda integrada

1. Como o NPSeeker projeta e avalia sondas

O NPSeeker recebe genomas-alvo e de controle e produz uma classificação de sondas candidatas. Os alvos são os organismos que você deseja detectar. Os controles são os organismos aos quais as sondas não devem se ligar, muitas vezes espécies próximas que poderiam ser confundidas com os alvos. A análise possui quatro etapas principais:

  • Identificar sequências compartilhadas: O NPSeeker examina os genomas em busca de todas as sequências consecutivas de k nucleotídeos, chamadas k-mers. Por exemplo, os 3-mers de ACGTA são ACG, CGT e GTA. Todo k-mer presente em todos os genomas-alvo torna-se uma sonda candidata. Para detectar todos os alvos com uma única sonda, sua sequência precisa ser compartilhada por todos eles. Como o DNA possui duas fitas complementares, o NPSeeker considera um k-mer e seu complemento reverso como equivalentes.
  • Filtrar candidatas: O programa descarta sequências pouco adequadas como sondas, por exemplo, aquelas com composição de bases muito desequilibrada, repetições longas da mesma base (como AAAA) ou tendência a se dobrar sobre si mesmas ou a se parear com outras cópias da sonda. Assim, evita cálculos mais caros com candidatas pouco promissoras.
  • Examinar os controles: Para cada candidata restante, o NPSeeker procura nos genomas de controle correspondências exatas, correspondências aproximadas com poucas diferenças de bases e ocorrências de fragmentos mais curtos da sonda.
  • Calcular e classificar as pontuações: O NPSeeker calcula quatro componentes para cada candidata e os combina em uma pontuação geral.
ExclusivityPresença nos alvos e baixa ocorrência nos controles
PurityPoucas sequências semelhantes ou fragmentos coincidentes nos controles, reduzindo o risco de ligação indesejada
UnfoldabilityBaixa tendência a se dobrar sobre si mesma, mantendo a sonda acessível para hibridização com o alvo
AffinityForça de ligação prevista a partir da energia livre de hibridização (energia liberada quando a sonda se liga ao alvo)

Os quatro componentes e a pontuação geral variam de 0 a 100; valores maiores indicam propriedades previstas mais favoráveis. Por padrão, os quatro componentes têm o mesmo peso. Essas pontuações ajudam a priorizar candidatas para validação experimental; não representam sinais BioFET medidos nem garantem o desempenho em experimentos.

Se os genomas-alvo forem muito diferentes e compartilharem poucos k-mers, o NPSeeker os divide em grupos e identifica candidatas para cada grupo separadamente. Consulte o capítulo 4 para saber como funcionam o agrupamento e os modos de saída. As equações das pontuações e os detalhes do algoritmo estão no artigo científico.

2. Preparação dos genomas-alvo e de controle

Os dois primeiros argumentos na linha de comando indicam, nesta ordem, as entradas de alvo e controle. As opções vêm depois:

./bin/npseeker <target> <control> [options]

Prepare um arquivo FASTA para cada genoma. FASTA é um formato de texto simples para sequências de DNA, geralmente com extensão .fasta, .fna ou .fa. As entradas de alvo e controle podem ser especificadas independentemente como pastas, listas de arquivos ou arquivos FASTA individuais.

2.1 Entradas por pasta

Ao receber uma pasta, o NPSeeker lê os arquivos terminados em .fasta, .fna ou .fa e considera cada arquivo um genoma. As extensões podem estar inteiramente em minúsculas ou em maiúsculas (por exemplo, .FASTA). As subpastas não são percorridas.

./bin/npseeker targets/ controls/

Arquivos compactados (.gz, .zst) dentro de uma pasta não são incluídos. Para utilizar arquivos FASTA compactados, informe-os por meio de uma lista de arquivos.

2.2 Listas de arquivos

Uma lista de arquivos é um documento de texto simples que contém um caminho de arquivo FASTA por linha. Coloque @ antes do nome da lista para indicar ao NPSeeker que a entrada é uma lista:

./bin/npseeker @target.list @control.list

Por exemplo, o conteúdo de target.list pode ser:

# Three target genomes
genomes/strain_A.fasta
genomes/strain_B.fna.gz
/data/others/strain_C.fa
  • Linhas vazias e linhas iniciadas por # são ignoradas, permitindo a inclusão de comentários.
  • Caminhos relativos são interpretados a partir da pasta na qual você executa o NPSeeker, e não da pasta que contém a lista.
  • Os arquivos relacionados podem estar em pastas diferentes ou ser arquivos FASTA compactados com gzip (.gz) ou zstd (.zst).
  • Com -cluster-order input, a ordem dos arquivos na lista determina a ordem de processamento durante o agrupamento (capítulo 4).

Um arquivo fornecido sem @ e cuja extensão não seja reconhecida como FASTA também é interpretado como uma lista. Mesmo assim, recomenda-se usar @ para deixar a intenção explícita.

2.3 Um único arquivo FASTA

Se o conjunto de alvos ou controles contiver apenas um genoma, você pode informar diretamente o arquivo FASTA correspondente. Arquivos FASTA compactados também são aceitos:

./bin/npseeker strain_A.fasta controls/

2.4 Conteúdo FASTA e validação das entradas

  • Um arquivo FASTA pode conter vários registros de sequência, como cromossomos e plasmídeos. Todos os registros do mesmo arquivo são tratados como um único genoma.
  • O NPSeeker aceita A, C, G e T, tanto em maiúsculas quanto em minúsculas. Outras letras, como N, interrompem a sequência; k-mers que atravessam essas posições são excluídos.
  • O programa verifica se os arquivos de entrada estão no formato FASTA e interrompe a execução com uma mensagem de erro se algum arquivo não existir ou for inválido (seção 7.2).
  • Um mesmo arquivo não pode estar nas entradas de alvo e controle ao mesmo tempo. Se isso ocorrer, o NPSeeker informa a duplicação e interrompe a análise.

A escolha dos genomas-alvo e de controle afeta diretamente a classificação das sondas. Os controles devem incluir organismos que poderiam ser confundidos com os alvos na aplicação pretendida, em vez de uma seleção arbitrária de espécies sem relação com eles.

3. Interpretação dos resultados e seleção de sondas

3.1 Resultados exibidos na tela

Sem -o, o NPSeeker mostra na tela as primeiras -top sondas (200 por padrão), com as colunas Rank, Probe, os quatro componentes de pontuação, Score e Tm. Com -o, os resultados detalhados são gravados em arquivos, e a tela passa a listar os arquivos gerados. Acrescente -v para acompanhar os parâmetros e o tempo gasto em cada etapa do processamento.

3.2 Arquivos de saída

Por exemplo, -o result/ salva os resultados em arquivos CSV (valores separados por vírgulas), o formato padrão:

cluster_N_probes.csvSondas candidatas classificadas; N é o número do grupo, começando em 0
cluster.csvGrupo atribuído a cada genoma
flag.csvParâmetros utilizados na análise

Use -format txt para produzir tabelas alinhadas por espaços, mais fáceis de ler diretamente. Os arquivos CSV são convenientes para planilhas, como o Excel, e para outros programas. A quantidade de arquivos de sondas depende do modo single ou multi (capítulo 4).

As colunas de cluster_N_probes.csv são:

RankPosição da sonda na classificação
ProbeSequência da sonda, no sentido 5' para 3'
TgtOcorrências nos genomas-alvo
CtlOcorrências exatas nos genomas de controle; quanto menos, melhor
ExclusPontuação Exclusivity, calculada a partir de Tgt e Ctl
MMsPontuação de correspondências aproximadas nos controles; quanto menor, melhor
SubseqPontuação de fragmentos menores encontrados nos controles; quanto menor, melhor
PurityPontuação Purity, calculada a partir de MMs e Subseq
SelfAnTendência a se dobrar sobre si mesma (self-annealing); quanto menor, melhor
DimerTendência a se parear com outra cópia (dimer); quanto menor, melhor
UnFoldPontuação Unfoldability, calculada a partir de SelfAn e Dimer
AffiniPontuação Affinity, baseada na energia livre de ligação
ScoreMédia ponderada dos quatro componentes de pontuação
TmTemperatura de fusão (°C), na qual metade dos dúplex sonda-alvo está dissociada; não entra no cálculo de Score

Exclus, Purity, UnFold, Affini e Score variam de 0 a 100; quanto maior o valor, melhor. Quando os alvos são divididos em vários grupos, Tgt também inclui correspondências aproximadas em genomas-alvo de outros grupos. Por isso, essa coluna nem sempre representa somente ocorrências exatas.

O arquivo cluster.csv contém três colunas: Group (target ou control), Cluster (número do grupo de um alvo; vazio para controles) e File (nome do arquivo). O arquivo flag.csv contém Option e Value, permitindo conferir os parâmetros usados na análise.

Se a pasta de saída não existir, o NPSeeker a criará. Uma pasta existente, mas vazia, também é aceita. Se a pasta já contiver arquivos, o programa interrompe a execução para não substituí-los. Utilize -w somente quando desejar substituir resultados anteriores: o NPSeeker exclui seus arquivos de resultados anteriores (cluster_N_probes, cluster e flag), mas preserva arquivos não relacionados. Antes de usar -w, confira se os resultados antigos não serão mais necessários.

3.3 Como escolher as sondas

Score é um bom ponto de partida, mas a seleção das sondas não deve depender apenas da pontuação geral. Dependendo da aplicação, considere também:

  • Ctl: Um valor maior que zero indica que existe uma sequência idêntica em um genoma de controle. A sonda pode, portanto, se ligar a um organismo não alvo e produzir reatividade cruzada.
  • Tgt: Um número maior de ocorrências pode favorecer a intensidade do sinal, mas também pode indicar uma região repetitiva. Tgt não prevê diretamente a intensidade do sinal.
  • Purity e UnFold: Esses componentes ajudam a comparar os riscos de ligação indesejada e de dobramento da sonda sobre si mesma.
  • Tm: Se o ensaio exigir determinada temperatura ou combinar várias sondas, compare suas temperaturas de fusão. De preferência, sondas usadas no mesmo ensaio devem apresentar valores de Tm próximos.

Você também pode pesquisar sequências semelhantes em outros organismos usando o NCBI BLAST ou avaliar possíveis estruturas de dobramento da sonda com o UNAFold (mfold). A página Results oferece links para ambos os serviços, mas eles enviam a sequência da sonda selecionada a um site externo (seção 6.2). A adequação da sonda a uma plataforma BioFET específica precisa, em qualquer caso, ser verificada nas condições experimentais pretendidas.

4. Agrupamento dos alvos e modos single e multi

Quando há poucos k-mers em comum entre todos os genomas-alvo, o NPSeeker divide os alvos em grupos (clusters). Os genomas são examinados um a um. Um genoma só é acrescentado ao grupo atual se o número de k-mers compartilhados por todos os integrantes, incluindo o novo genoma, continuar sendo pelo menos -min-shared. Caso contrário, o genoma é reservado para outro grupo. Esses grupos são formados para descobrir sondas candidatas; não representam classificações evolutivas ou filogenéticas.

A opção -cluster-order controla a ordem de análise dos genomas-alvo:

  • auto (padrão): Define uma ordem determinística com base na semelhança de k-mers entre os genomas. Para um mesmo conjunto de genomas, mudar a ordem dos arquivos de entrada não altera os grupos formados.
  • input: Mantém a ordem informada pelo usuário, por exemplo, a ordem de uma lista de arquivos. Use esta opção quando quiser que determinado genoma de referência seja o ponto de partida do primeiro grupo.

O valor padrão de -min-shared é 1: um genoma pode entrar no grupo desde que permaneça pelo menos um k-mer compartilhado por todos os integrantes. Assim, os alvos frequentemente formam um único grupo. Aumentar esse limite pode produzir mais grupos e alterar as sondas candidatas disponíveis em cada um.

Se houver mais de um grupo de alvos, -mode determina como as candidatas serão classificadas e salvas:

  • single (padrão): Reúne as candidatas de todos os grupos em uma única classificação e conserva apenas as -top primeiras sondas no arquivo cluster_0_probes.csv. Muitas das candidatas mais bem classificadas podem vir do mesmo grupo.
  • multi: Classifica as candidatas de cada grupo separadamente e conserva até -top sondas por grupo em cluster_0_probes.csv, cluster_1_probes.csv e assim por diante. Use este modo quando precisar de candidatas para cada grupo de alvos.

No modo multi, a escolha de sondas em cada grupo permite obter um conjunto de candidatas que, do ponto de vista computacional, cobre todos os grupos de alvos. A capacidade real de detecção ainda precisa de validação experimental. Consulte cluster.csv para saber quais genomas pertencem a cada grupo. Se nenhuma candidata de determinado grupo passar pelos filtros, o NPSeeker emitirá um aviso e salvará os resultados dos demais grupos.

5. Opções e parâmetros

Coloque as opções depois das entradas target e control. As opções que exigem um valor devem ser seguidas de um espaço e desse valor (por exemplo, -k 31). Opções de ativação, como -v, -w e --gui, não recebem valores. Algumas opções possuem nomes curtos e longos (por exemplo, -k e -kmer); ambos são aceitos. Valores numéricos podem usar notação científica: 1e7 corresponde a 10.000.000. Na linha de comando, use ponto como separador decimal, por exemplo -c 0.5, mesmo que em português seja comum escrever 0,5. As seções a seguir acompanham as categorias da saída de -help; o nome entre parênteses em cada título é a categoria correspondente. O Apêndice A reúne as opções para consulta rápida.

5.1 Comprimento das sondas e recursos computacionais (General settings)

-k, -kmer [inteiro, de 5 a 256; padrão: 25]

Define o comprimento da sonda em nucleotídeos. Escolha um valor apropriado para o ensaio. Conforme k aumenta, genomas-alvo divergentes têm menos chance de compartilhar sequências idênticas desse comprimento, e pode ser necessário formar mais grupos. O tempo de execução depende principalmente do tamanho dos genomas e da quantidade de candidatas: sondas mais longas não tornam necessariamente a análise mais lenta (consulte a Figura 4 do artigo).

-t, -threads [inteiro; padrão: 0]

Define o número de threads de processamento. O valor 0 utiliza todos os threads de hardware disponíveis. Reduza esse número se o computador também precisar ser usado para outras tarefas.

-m, -memory [tamanho; padrão: metade da memória física, até o limite de 8G]

Define o orçamento de memória para as principais etapas de processamento, por exemplo -m 8G ou -m 512M. Se a unidade for omitida, o valor será interpretado em GiB. Um orçamento menor aumenta a quantidade de processamento em lotes e pode tornar a análise mais lenta, mas não altera os resultados. A memória usada para carregar lotes de candidatas (-b) e outros dados de execução é adicional a esse orçamento (seção 5.5).

5.2 Arquivos de saída e registro da execução (Output)

-o, -out-dir [pasta; padrão: não salvar arquivos]

Especifica a pasta na qual os resultados serão salvos (seção 3.2). Sem -o, os resultados são exibidos na tela com menos colunas. Use uma pasta de saída se quiser guardar, comparar ou reproduzir uma análise posteriormente.

-w, --overwrite

Permite reutilizar uma pasta -o que não esteja vazia. Os arquivos de resultados anteriores do NPSeeker nessa pasta são removidos antes da gravação dos novos; os demais arquivos são preservados (seção 3.2).

-top [inteiro; padrão: 200]

Define a quantidade de sondas mais bem classificadas a serem apresentadas em cada classificação. Aumente o valor para examinar mais candidatas. Valores muito altos podem gerar arquivos maiores e exigir mais memória e tempo; escolha uma quantidade adequada à sua necessidade.

-format [csv ou txt; padrão: csv]

Controla o formato dos resultados. csv usa valores separados por vírgulas, apropriados para planilhas e outros programas; txt gera uma tabela alinhada por espaços para leitura direta.

-v, --verbose

Mostra informações adicionais, incluindo as entradas, os parâmetros, as etapas de processamento e o tempo gasto em cada uma. É útil para investigar problemas ou acompanhar análises longas. As análises iniciadas pela interface gráfica sempre usam registros detalhados.

5.3 Agrupamento e classificação (Target clustering, Probe ranking)

-cluster-order [auto ou input; padrão: auto]

Controla a ordem de processamento dos genomas-alvo durante o agrupamento. auto não depende da ordem dos arquivos de entrada; input segue a ordem informada. Consulte o capítulo 4 para detalhes e exemplos de uso.

-min-shared [inteiro; padrão: 1]

Define a quantidade mínima de k-mers que precisam permanecer compartilhados por todos os genomas de um grupo. Aumentar esse limite geralmente produz mais grupos, mas não garante que todos terão sondas adequadas (capítulo 4).

-mode [single ou multi; padrão: single]

Os modos só diferem quando os alvos formam vários grupos. single reúne as candidatas de todos os grupos em uma única classificação; multi gera classificações separadas para cada grupo. Consulte o capítulo 4 antes de escolher o modo.

-weights [pares KEY=WEIGHT separados por vírgulas; padrão: 1 por componente]

Altera o peso de cada componente na pontuação geral: exclusividade (exc), pureza (pur), baixa tendência ao dobramento (unf) e afinidade (aff). Por exemplo:

-weights exc=2,pur=2

Isso atribui o dobro do peso a exclusividade e pureza, mantendo os pesos de unf e aff em 1. A pontuação geral é calculada por:

Score = (w_exc*Exclus + w_pur*Purity + w_unf*UnFold + w_aff*Affini)
        / (w_exc + w_pur + w_unf + w_aff)

Os pesos podem ser zero, mas não negativos; pelo menos um deles deve ser positivo. Um componente com peso zero ainda é calculado, mas não contribui para Score. Aumentar um peso altera a classificação, mas não elimina as candidatas que tiverem pontuação baixa nesse componente.

-mm, -mismatch-cutoff [inteiro; padrão: parte inteira de k/10]

Define o número máximo de diferenças de nucleotídeos permitido ao buscar correspondências aproximadas da sonda nos genomas de controle para o cálculo de Purity. Um limite maior pode revelar mais correspondências aproximadas, mas também aumentar bastante o tempo de execução e o uso de memória. Esse limite deve ser menor que o comprimento da sonda.

5.4 Filtragem das sondas candidatas (Candidate filtering)

O NPSeeker filtra as candidatas antes de executar as comparações mais custosas com os genomas de controle. Se os critérios forem muito rigorosos, nenhuma candidata poderá ser aprovada. Nesse caso, você pode flexibilizar um ou mais dos limites abaixo.

-max-homopolymer [inteiro; padrão: 3]

Um homopolímero é uma sequência de nucleotídeos idênticos, como AAAA. Esta opção estabelece o comprimento máximo permitido para essas repetições: o valor padrão 3 aceita AAA, mas rejeita candidatas com AAAA ou sequências mais longas da mesma base. Aumentar o limite mantém mais candidatas com bases repetidas.

-c, -min-complexity [número de 0 a 1; padrão: 0.5]

Define a pontuação mínima de complexidade da sequência. Sequências com proporções mais equilibradas dos quatro nucleotídeos recebem pontuações maiores. Para passar pelo filtro, a candidata precisa ter pontuação acima desse limite.

-e, -min-entropy [número de 0 a 2; padrão: 1.5]

Define a pontuação mínima de entropia da sequência. A entropia indica a diversidade de nucleotídeos; padrões repetitivos, como ACACAC, apresentam baixa entropia. Para passar pelo filtro, a candidata precisa superar esse limite. Sondas mais curtas têm pontuações máximas possíveis menores de complexidade e entropia. Se um limite especificado exceder o máximo possível para o comprimento escolhido, o NPSeeker emitirá um erro e informará o valor máximo.

-prefilter [T ou F; padrão: T]

Determina se as candidatas serão filtradas pela pontuação Unfoldability antes da busca nos genomas de controle. T elimina as candidatas com pontuação inferior a -min-unfold, reduzindo a quantidade de comparações. F desativa essa filtragem antecipada, mas a pontuação Unfoldability continua sendo calculada para cada candidata.

-min-unfold [número de 0 a 100; padrão: 75]

Define o limite de Unfoldability utilizado na filtragem antecipada. Reduzi-lo preserva mais candidatas com possível tendência ao dobramento, podendo aumentar o trabalho nas comparações posteriores. Se nenhuma candidata de um lote alcançar o limite, o NPSeeker desativa a pré-filtragem apenas para aquele lote. Por exemplo, a sonda para bactérias Gram-positivas avaliada experimentalmente no artigo tem Unfoldability de 72,54; utilize -min-unfold 70 para reproduzir sua classificação (capítulo 8).

5.5 Opções avançadas (Advanced)

Os valores padrão são apropriados para a maioria das aplicações.

-b, -batch-size [inteiro; padrão: 1e7]

Define quantos k-mers candidatos são carregados e filtrados por vez. Com k = 25, cada candidata ocupa aproximadamente 170 bytes. Assim, o lote padrão de 10 milhões de candidatas requer cerca de 1,58 GiB, além do orçamento de memória definido por -m. Reduza este valor em computadores com pouca memória disponível; lotes menores podem aumentar o tempo de execução.

-s, -min-subseq [inteiro; padrão: 7]

Define o comprimento mínimo dos fragmentos de sonda considerados no cálculo de Purity. Funciona em conjunto com -subseq-step.

-subseq-step [inteiro; padrão: arredondamento de k/10 para cima]

Define quanto o comprimento dos fragmentos diminui a cada etapa do cálculo de Purity. Por exemplo, para k = 25, o passo padrão é 3, portanto os comprimentos analisados são 22, 19, 16, 13, 10 e 7. Um passo menor examina mais comprimentos de fragmentos e aumenta o trabalho de comparação.

-tmp-dir [pasta; padrão: pasta temporária do sistema]

Define o local dos arquivos intermediários. O NPSeeker cria sua própria subpasta nesse local e a remove quando a execução termina normalmente ou é interrompida com Ctrl-C. Se o disco do sistema tiver pouco espaço livre, escolha uma pasta em outro disco.

-gui-port [inteiro]Porta de acesso à interface (número após os dois-pontos na URL); padrão: escolhida automaticamente
--no-browserMostra a URL da interface sem abrir o navegador
--tabAbre a interface em uma aba do navegador

6. Interface gráfica

O NPSeeker inicia um pequeno servidor web em seu computador, acessível somente nesse computador (127.0.0.1), e utiliza o navegador como interface. O próprio NPSeeker executa a análise: seus arquivos genômicos não são enviados para um site externo. Com os mesmos parâmetros, a interface gráfica e a linha de comando produzem resultados idênticos.

6.1 Iniciar e acessar a interface

  • Windows: Clique duas vezes em npseeker.exe na pasta bin/ ou execute .\bin\npseeker.exe --gui pelo Prompt de Comando. O programa abre uma janela de console (janela de texto que mostra suas mensagens). Mantenha essa janela aberta enquanto utilizar a interface.
  • macOS, Linux: Execute ./bin/npseeker --gui em um terminal.

Normalmente, o NPSeeker abre o navegador automaticamente e também mostra o endereço da interface no terminal, por exemplo:

http://127.0.0.1:53817/?t=1a2b3c...

A parte após ?t= é um token de acesso exclusivo da sessão atual. Se o navegador não abrir, copie a URL completa e cole-a na barra de endereços. Como o endereço contém um token de acesso, evite compartilhá-lo desnecessariamente.

Por padrão, a interface abre em uma janela separada. Navegadores como Edge e Chrome usam uma janela em estilo de aplicativo, sem barra de endereços; o Firefox abre uma nova janela. Use --tab para abrir a interface em uma aba do navegador padrão.

6.2 Páginas principais

DesignSelecione os genomas Target e Control, uma pasta de saída opcional e o comprimento da sonda. É possível escolher pastas ou arquivos FASTA individuais, inclusive arquivos compactados de diferentes locais. "Tick all" seleciona todos os arquivos de uma pasta; "Pick folder" e "Pick files" abrem as caixas de seleção de arquivos do sistema operacional. Expanda as opções adicionais quando necessário; campos vazios usam os valores padrão. "Check" valida os dados e parâmetros, e "Go" inicia a análise.
RunMostra a etapa atual, o progresso e o registro da execução. "Cancel" interrompe a análise.
ResultsPermite consultar as sondas classificadas, suas sequências e pontuações. Clique no cabeçalho de uma coluna para ordenar os dados; Rank conserva a classificação original do NPSeeker. Clique em uma sonda para visualizar seu complemento reverso, a temperatura de fusão ou copiar a sequência. Baixe os arquivos individualmente ou todos em um arquivo zip.
HelpApresenta o manual do usuário e permite trocar de idioma.
AboutMostra informações sobre o programa, o artigo, os autores e os contatos.

A página Results também oferece links para dois serviços externos:

  • BLAST at NCBI: Abre o NCBI BLAST com a sequência da sonda selecionada para procurar sequências semelhantes em outros organismos.
  • Fold at UNAFold: Envia a sequência ao UNAFold (mfold) para prever estruturas de dobramento do DNA, usando os valores padrão do formulário do site (37 °C, 1 M Na+).

Esses dois serviços exigem conexão com a internet e transmitem a sequência da sonda selecionada para um site externo. Antes de usá-los com sequências ainda não publicadas, verifique se seu compartilhamento é apropriado.

Se nenhuma pasta de saída for especificada, a interface gráfica guarda temporariamente os resultados no disco local. Esses arquivos são apagados quando a interface é encerrada. Baixe os arquivos que desejar conservar antes de sair.

6.3 Fechar a interface e preservar os resultados

  • "Close" fecha apenas a página do navegador; o NPSeeker continua funcionando. Para voltar à interface, abra novamente a URL mostrada no console.
  • "Exit" encerra a interface e interrompe qualquer análise ainda em andamento. Fechar a janela do console ou pressionar Ctrl-C também encerra o programa.
  • Se todas as páginas da interface permanecerem fechadas por mais de cinco minutos, sem uma análise em execução, o NPSeeker será encerrado automaticamente. Os resultados temporários ainda não baixados serão apagados.

A interface solicita confirmação ao clicar em "Exit" ou "Close" e avisa quando há uma análise em andamento ou resultados temporários que ainda não foram baixados.

Se você informou uma pasta de saída, os resultados permanecem nela. Executar outra análise com a mesma pasta substitui os arquivos de resultados anteriores do NPSeeker, mas preserva os arquivos não relacionados.

Você pode selecionar Auto, Dark ou Light como tema da interface. Auto acompanha a aparência clara ou escura do sistema operacional.

6.4 Acessar a interface em um servidor remoto

Se o NPSeeker estiver sendo executado em um servidor remoto, você poderá acessar sua interface pelo navegador do seu computador usando um túnel SSH (uma conexão criptografada que encaminha uma porta local ao servidor). Primeiro, inicie o NPSeeker no servidor e especifique uma porta:

./bin/npseeker --gui --no-browser -gui-port 53817

Depois, no seu próprio computador, abra um terminal e estabeleça o túnel SSH:

ssh -L 53817:127.0.0.1:53817 username@server

Mantenha a conexão SSH aberta. No navegador local, informe a URL completa exibida pelo NPSeeker no servidor. Você também pode escolher outra porta local, por exemplo:

ssh -L 9000:127.0.0.1:53817 username@server

Nesse caso, substitua o endereço base por http://127.0.0.1:9000/, mantendo o token de acesso original ?t=.

No acesso remoto, a interface mostra os arquivos do servidor, não os do seu computador. "Pick folder" e "Pick files" também abrem caixas de seleção no servidor. Se ele não tiver ambiente gráfico, essas caixas não estarão disponíveis; utilize o navegador de arquivos integrado à interface do NPSeeker.

6.5 Localização dos arquivos de configuração

Para facilitar o uso em sessões futuras, o NPSeeker guarda as pastas usadas recentemente em recent.txt e o último local selecionado em lastpick.txt. Esses pequenos arquivos ficam em:

Linux~/.config/npseeker/
macOS~/Library/Application Support/npseeker/
Windows%AppData%\npseeker\

Os arquivos intermediários criados durante a análise ficam na pasta temporária do sistema ou no local definido por -tmp-dir, não nas pastas de configuração acima.

7. Desempenho e solução de problemas

7.1 Memória, tempo de execução e arquivos temporários

  • Memória: -m limita a memória usada pelas principais etapas de processamento. Os lotes de candidatas carregados com -b e outros dados de execução exigem memória adicional. Se houver pouca memória disponível, reduza tanto -m quanto -b.
  • Threads: -t 0 utiliza todos os threads de hardware disponíveis. Reduza esse número se o computador também estiver executando outras tarefas.
  • Tempo: A duração depende do tamanho dos genomas, da quantidade de candidatas compartilhadas, de -mm, da memória disponível, do hardware e da velocidade do disco. Aumentar k não necessariamente torna a análise mais lenta. Use -v para verificar o tempo gasto em cada etapa.
  • Arquivos temporários: O NPSeeker cria arquivos intermediários durante a análise. Seu tamanho depende dos dados e do orçamento de memória; um orçamento menor geralmente exige mais espaço temporário em disco. Garanta espaço livre suficiente. Os arquivos temporários são removidos após a conclusão normal ou a interrupção com Ctrl-C.

7.2 Mensagens de erro comuns

Mensagens referentes a opções ou parâmetros inválidos começam com "npseeker:". Erros de entrada, saída ou execução começam com "Error:". Veja alguns problemas comuns e como resolvê-los. Se target for substituído por control, o erro se refere à entrada de controle.

  • Error: target: no FASTA file (*.fasta, *.fna or *.fa) in the folder ...
    A pasta não contém arquivos com as extensões FASTA reconhecidas. Para arquivos compactados, use uma lista de arquivos (seção 2.2).
  • Error: target: "..." is not found
    O caminho está incorreto. Lembre-se de que caminhos relativos começam na pasta em que o NPSeeker foi executado.
  • Error: target: "..." is not a FASTA file: ...
    O arquivo não possui formato FASTA válido; o texto após os dois-pontos explica o problema.
  • Error: target: the FASTA file "...", listed in "...", is not found
    Um arquivo indicado na lista não foi encontrado.
  • Error: target and control: ...; a genome cannot be both a target and a control
    O mesmo arquivo aparece nos dois conjuntos de entrada.
  • Error: -o: the folder "..." already exists and is not empty; give -w ...
    A pasta de saída não está vazia. Escolha outra pasta ou acrescente -w caso seja seguro substituir os resultados anteriores.
  • npseeker: option -mm: must be less than the probe length (-k)
    O limite de diferenças de bases deve ser menor que o comprimento da sonda.
  • npseeker: option -c: no probe of 8 nt has a complexity score above 0.431 ...
    O limite escolhido ultrapassa a maior pontuação possível para esse comprimento de sonda (0.431 neste exemplo). Reduza o limite (seção 5.4).
  • Error: -tmp-dir: cannot create the folder "...": ...
    O NPSeeker não conseguiu criar a pasta temporária. Verifique o caminho e as permissões de escrita.

7.3 Saída padrão e saída de erro padrão

O texto exibido no terminal passa por dois fluxos distintos: saída padrão (stdout) e saída de erro padrão (stderr). Normalmente, ambos aparecem na tela. A diferença fica evidente ao redirecionar a saída para um arquivo, por exemplo, acrescentando > out.txt ao comando: stdout será gravado nesse arquivo, enquanto stderr continuará aparecendo na tela.

O NPSeeker escreve os resultados, os registros detalhados de -v e as mensagens de erro em stdout. Notas iniciadas por Note:, avisos iniciados por Warning: e barras de progresso são enviados a stderr. Dessa forma, o arquivo redirecionado fica livre das mensagens de progresso, mas os avisos continuam visíveis no terminal.

7.4 Nenhuma sonda encontrada ou execução lenta

Se nenhuma candidata passar pelos filtros, o NPSeeker mostrará:

Warning: no probe passed the filters; relax the thresholds
         (-max-homopolymer, -c, -e, -min-unfold) to let probes pass.

Experimente flexibilizar -min-unfold, -c, -e ou -max-homopolymer (seção 5.4). Se os genomas-alvo compartilharem poucos k-mers, tente diminuir -k ou ajustar -min-shared e -mode (capítulo 4). Use -v para verificar quantas candidatas permanecem e quanto tempo cada etapa consome.

Se a análise estiver inesperadamente lenta, verifique se a memória exigida por -m, pelos lotes de candidatas (-b) e pelas demais tarefas cabe na memória física disponível. Caso contrário, o sistema operacional poderá transferir dados da memória para o disco, reduzindo muito o desempenho. Se -mm estiver alto, compare a execução com seu valor padrão. Em conjuntos de dados grandes, confira também a velocidade do disco e o espaço livre na pasta temporária.

8. Exemplos de uso

Os exemplos abaixo usam a sintaxe do macOS e do Linux. No Windows, substitua ./bin/npseeker por .\bin\npseeker.exe e use \ no lugar de / nos caminhos de arquivos. Cada exemplo pode ser executado separadamente. Se result/ já contiver arquivos de uma execução anterior, escolha outra pasta de saída ou acrescente -w somente se pretender substituir os resultados anteriores do NPSeeker.

Análise básica, salvando os resultados em result/:

./bin/npseeker dat/sample/S.aureus/ dat/sample/yeast/ -o result/

Ler os alvos de uma lista de arquivos e agrupá-los na ordem indicada:

./bin/npseeker @target.list controls/ -cluster-order input -o result/

Projetar sondas de 31 nucleotídeos com 32 threads e 16 GiB de memória:

./bin/npseeker targets/ controls/ -k 31 -t 32 -m 16G -o result/

Dar maior peso a exclusividade e pureza na pontuação geral:

./bin/npseeker targets/ controls/ -weights exc=2,pur=2 -o result/

Buscar sondas candidatas separadamente para vários grupos de alvos:

./bin/npseeker targets/ controls/ -min-shared 20000 -mode multi -o result/

Reproduzir a classificação das sondas bacterianas da Tabela 3 do artigo, usando os parâmetros do estudo em vez de todos os padrões (os conjuntos de dados são um download separado; veja a seção 0.2):

./bin/npseeker dat/datasets/GP/ dat/datasets/GN/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GP_probes/
./bin/npseeker dat/datasets/GN/ dat/datasets/GP/ -k 23 -min-unfold 70 \
    -weights exc=2,pur=2 -o GN_probes/

O parâmetro -min-unfold 70 permite incluir a sonda para bactérias Gram-positivas avaliada experimentalmente, cuja pontuação Unfoldability é 72,54. Nos comandos acima, \ ao final da linha indica a continuação do comando no macOS e no Linux. No Prompt de Comando do Windows, use ^; no PowerShell, use o acento grave (`). Outra opção é digitar o comando inteiro em uma única linha.

Parte do conjunto de dados usado no artigo vem do ATCC Genome Portal, cujos termos de uso não permitem a redistribuição. Por isso, a pasta dat/datasets/ contém dados correspondentes do NCBI; o arquivo dat/datasets/sources.txt relaciona cada arquivo ao conjunto de dados do artigo. Com esses dados, as sequências e as posições das duas sondas da Tabela 3 são reproduzidas exatamente, mas o número de candidatas, as contagens de ocorrências e as pontuações diferem ligeiramente. Um desses genomas, S. enterica ATCC 43976, só tem no NCBI uma montagem incompleta (falta parte do seu rRNA 23S). Se ele for deixado de fora quando GN for o alvo (desmarque-o na interface gráfica ou use a lista de arquivos @dat/datasets/GN-without-43976.list na linha de comando), o número de candidatas volta a 65, e as 8 primeiras sondas da Tabela Suplementar S3 também coincidem com as do artigo.

Salvar os resultados como tabelas legíveis e incluir mais sondas candidatas:

./bin/npseeker targets/ controls/ -format txt -top 1000 -o result/
